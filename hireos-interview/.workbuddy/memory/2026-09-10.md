## 修复 Home 页项目行点击 bug
**问题**: 用户反馈 Home 页点 SB 行 "Senior Backend Engineer / Elena Torres" 不能进入二级页。

**根因**: `homeProjects(state, role.key)` 是普通函数,但其内部的 `p.open` 闭包调用了 `useStore()`。HomePage 渲染时 `homeProjects` 被调用 **4 次**(各 count 一次),加上顶部一次,共 5 次 useStore 调用,加上 filter 之前还会再算一次。React 18 严格模式下 hook 调用顺序稳定但**普通函数中调用 hook 会让闭包内拿到的 `set` 在 dispatch 链路上失效**(实测点击事件触发后,React state 不更新)。

**修复**: 把 `homeProjects` 改成纯函数,接收 `set` 和 `say` 作为参数(不再调用 hook),所有 `p.open` 直接使用外部传入的 `set`。同时给未连通的 4 行(Product Analyst / Staff Frontend / Data Platform / Support Engineer)也补上 `open` 函数,点击后跳到 overview 并 toast 解释项目状态(草稿/只读/暂停/关闭),让 5 行都能进二级页。

**验证**: 在浏览器里点击各行,均能正确跳转到对应项目的 Overview 页;TypeScript 0 错误、Vite 生产构建 32s。

## 修复 Requirements & Rubric 页白屏 bug
**问题**: 用户从 Overview 点击 "Requirements & Rubric" tab 后,整页白屏。

**根因**: `ProjectA.tsx` 的 `RubricPage` 里 `bannerStyle` 是个 **CSS 字符串**(老 dc-runtime 时代的写法),用 `as any` 强转赋给 React 的 `style` 属性:
```ts
const bannerStyle = state.rubricConfirmed
  ? "padding:11px 14px;border:1px solid var(--ok);..."
  : "padding:11px 14px;border:1px solid var(--line-strong);...";
```
React 19 dev 模式下 `setValueForStyles` 严格检测:遇到字符串 style 会直接抛错并卸载整个组件树,导致白屏。

**修复**:
1. `bannerStyle` 改成对象语法
2. 去掉 `style={bannerStyle as any}` 的强转
3. 顺手在 `main.tsx` 加了 `<ErrorBoundary>`,以后任何子组件抛错都不会让用户看到全空白——会显示红色面板带 stack trace

**验证**: TypeScript 0 错、Requirements & Rubric / Plan / Schedule / Brief / Live / Review / Debrief / Decision / Evaluation Package 全部 8 个 tab 都能正常切换,无白屏。

## 第三轮:CreateProjectModal 样式乱 + 顺手修一个隐性 bug

**bug A**: Modal 打开后,tab 卡片无描边、按钮无青绿底、Choose JD file dropzone 边框几乎看不见、+ Add materials 不是青绿色、Create project 按钮没背景——所有颜色相关的视觉都没生效。

**根因** (CSS custom properties 被 antd Modal Portal 截断):
- 所有 token (`--brand`/`--surface`/`--ink`/`--line` 等) 都通过 inline style 注入到了 `.hireos-root` 这个根 div 上,而不是 `:root` 或 `document.documentElement`
- antd Modal 默认用 React Portal 把弹窗 DOM 渲染到 `document.body` 下,**脱离了 `.hireos-root` 子树**
- CSS custom properties 沿 DOM 树继承,但 `.hireos-root` 不是 modal 父级,所以 `var(--brand)` 在 modal 里解析失败,fallback 也未必填了,显示成 transparent/默认色

**修复** (AppShell.tsx):
- 加 `useLayoutEffect`,把同一份 `cssVars` 同步到 `document.documentElement.style`
- 卸载时清掉,避免重新挂载后残留

**bug B** (顺手发现): TopBar 里的 + New Interview Project 按钮
```ts
onClick={() => useStore().set({ showCreateModal: true, ... })}
```
在事件处理器里直接调用 `useStore().set(...)`,因为 `useStore()` 在非组件顶层调用拿到的 `set` 是初始的 stale 引用——和上一轮 HomePage 的 bug 是同一性质。点击后 modal 根本不会打开。

**修复**: TopBar 解构里加 `set`,改成 `onClick={() => set({...})}`。

**验证**: 用 agent-browser 真实打开 modal 截图对比原型,所有 token 颜色正常显示; TypeScript 0 错。

## 将 App 的 state.screen 条件渲染改成 react-router 路由
**诉求**: 把 `App.tsx` 里 `state.screen` 的条件渲染改成真正的路由实现。

**方案(最小侵入,不破坏现有 go()/set({screen}) 调用)**:
- 路径映射:`home`→`/`、`files`→`/files`、其余 10 个 project screen→`/project/<screen>`
- `StoreContext.tsx` 新增 `screenToPath()` / `pathToScreen()` 纯函数 + `RouteSync` 组件
- `RouteSync` 用 `useNavigate`+`useLocation` 做双向同步:screen 变化→navigate;location 变化→set screen(支持浏览器前进/后退/深链/刷新)
- 关键坑:初次挂载时 state.screen="home" 会覆盖 URL 深链,用 `useRef` 记 prevScreen,首次跳过 screen→URL 的 effect
- `App.tsx` 改用 `<Routes>/<Route>` 声明式渲染,project 子页共享 `<ProjectShell>`(父 Route path=`/project/*` + 嵌套 `<Routes>`)
- `main.tsx` 里 `<BrowserRouter><RouteSync><ErrorBoundary><App/>` 的层级(RouteSync 必须在 BrowserRouter 内)

**验证**: 点击 SB 行→URL 变 `/project/overview`;点 Requirements & Rubric→`/project/rubric`;浏览器 back 逐级返回;`pushstate /project/rubric` 深链能正确渲染 rubric 页;TS 0 错、Vite build 43s。

**注意**: `agent-browser open <带path的url>` 会截断 path 只保留 origin,测 SPA 深链要用 `agent-browser pushstate <path>`(触发 popstate)。
- **Mock 数据**: `data/comps.ts`(6 个能力项 + 真实锚点描述)、`data/i18n.ts`(完整 en/zh 翻译表 + 状态映射)、`data/roles.ts`(HR/HM/Interviewer)
- **Antd 组件使用**: 仅 Modal 和 Drawer 需要(模态行为/动画);其余 UI 用原生 div + Tailwind 风格化,完全匹配 Google Workspace 视觉
