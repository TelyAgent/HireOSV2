# HireOS 实时面试 Zoom 接入实现计划 v1.0

日期：2026-09-11  
状态：待确认，尚未开始接入。本文只规定实施范围，不代表相关能力已上线。

## 1. 目标与实施边界

在现有 `src/pages/project/LivePage.tsx` 内接入 Zoom Meeting SDK for Web 的 Component View，使面试官在 HireOS 内参加真实会议，候选人通过 Zoom 原生邀请链接参会。

遵循以下原则：

- 保留当前页面外壳、问题区、侧栏和整体布局，不重新设计详情页。
- 仅将视频占位区替换为真实会议组件，并补充必要的连接、失败和退出状态。
- Zoom 组件内部采用 SDK 支持的界面，不承诺将其控件 1:1 改造成现有模拟按钮。
- 不同步改造评分标准、面试计划、排期、评审、汇总、决定或评估包业务。
- 首期只接真人会议；实时转写、AI 建议、云录制和 RTMS 为后续独立阶段。
- 未接通的能力不得显示为已运行、已保存或已有真实证据。

官方依据：Component View 支持把会议组件放入网页，面向桌面浏览器，移动端应另用 Client View；部分功能与 Client View 不同。Meeting SDK 用于真人参会，AI 记录与实时媒体应走 RTMS。[Component View 文档](https://developers.zoom.us/docs/meeting-sdk/web/component-view/)

## 3. 推荐首期参会方式

先用开发者账户所属的测试会议验证，主持人通过 Zoom 客户端开会；面试官在 HireOS 内以普通参会者加入，候选人通过普通 Zoom 链接加入。

这样首轮验证不依赖网页主持人 OAuth/ZAK、自动创建会议、外部客户账户审核或 RTMS。等待室及会议身份校验仍遵循 Zoom 设置，主持人负责放行。

SDK JWT 在 NestJS 生成；首期服务端固定参会角色为 attendee。网页主持人能力另行通过用户授权与 ZAK 实现。开发者账户之外的会议需要应用审核及适用的 ZAK/OBF 授权，不能承诺输入任意会议号即可加入。[Zoom 授权说明](https://developers.zoom.us/docs/meeting-sdk/auth/)

### 开始真实联调前所需条件

1. 可使用 Meeting SDK 的 Zoom 应用及对应 Client ID、Client Secret。
2. 同一开发者账户所属的测试会议、会议密码、主持人和第二台参会设备。
3. 确认账户会议时长、并发和必要功能权益满足测试，不默认免费额度足够。
4. 确定测试浏览器、网络环境和开发部署地址，检查摄像头、麦克风权限。
5. 密钥只写入后端忽略提交的环境变量；前端仅持有必要的运行时参会数据。

## 4. 分阶段交付

### P0：接入准备与兼容性验证

- 固定 SDK 版本，在现有 React 19、Vite、AntD 环境中验证构建与初始化。
- 验证 SDK 资源加载、浏览器要求、CSP、必要的跨域隔离配置；按所选版本文档设置，不盲目全站增加 COOP/COEP。
- 记录原页面桌面/窄屏截图，作为后续非会议区域的回归基线。
- 单独记录既有构建问题，避免把无关修复混入会议改造。

完成条件：确认测试账户、依赖版本和运行环境可用；未满足时不假报真实参会成功。

### P1：LivePage 真人会议 PoC（建议优先实施）

- 只在开发模式下，将后端配置的一场测试会议挂到当前 LivePage。
- 测试会议按后端白名单配置，不提供可为任意会议号签名的接口。
- 主持人外部开会，HireOS 内点击加入；候选人外部参会，不接触 HireOS 工作区或评分信息。
- 加入、双向音视频、共享屏幕、等待室、退出、失败重试按 SDK 实际能力验证。
- 进入真实模式后，保留侧栏位置，但转写、AI、录制显示未接入；笔记仅标为本地草稿，不上传、不宣称已持久化。
- 问题等尚未接通的区域明确为演示内容；PoC 不把假问题或假完成状态写入真实项目。
- 离开页面或切换轮次前先确认并退出当前会议；清理媒体和事件订阅。
- PoC 禁用模拟“完成并评审”的业务提交，保留普通导航；不改 Review 页面。
- 不引入项目路由或数据库变更；这一阶段验证的是会议嵌入，而非完整业务闭环。

完成条件：两台真实设备可通话与共享屏幕，退出后停止本页媒体使用，不改动其他页面。

### P2：真实项目、轮次与面试记录绑定

这是 PoC 通过后的独立交付，不与首轮 SDK 验证捆绑：

- 建立最小轮次与场次模型，每个场次属于一个明确的项目和轮次。
- 后端登记经校验的测试账户会议绑定；暂不建设全套排期 UI 或自动创建会议。
- 增加 `sessionId` 上下文入口，例如 `/project/live?sessionId=...`，刷新后由后端反查项目和轮次。
- 真实模式未传或无权访问 `sessionId` 时显示明确错误，不回退到最近访问的项目或演示人物。
- 全局现有跳转可能丢弃查询参数，因此该入口先作为显式联调链接使用；首页/计划页与真实场次导航衔接需单独确认，不顺带全站改路由。
- 标题、候选人和轮次信息来自真实场次；未接问题计划时显示无已关联问题，不继续显示固定题目。
- 人工笔记按场次和作者保存，带版本校验、失败提示和离页补保存，不覆盖其他面试官内容。
- “完成面试”提交业务状态；必须先成功保存笔记并确认离会处理。接口失败留在本页，不显示完成。
- 完成只记录本场次状态，不把数据强行接入仍是 mock 的 Review，不表示评分或评估包已可用。

完成条件：项目与轮次不串数据、刷新可恢复笔记、重复完成幂等、接口越权测试通过。

### P3：网页主持人与会议管理（后续）

- 用户授权后获取 ZAK，在网页内以主持人身份启动会议。
- 增加自动创建/更新会议、会议事件回调和会议信息同步。
- 回调单独验签，处理重复、乱序、重放与会议多次开启；不得信任浏览器上报来认定所有人已结束会议。
- 客户自行绑定外部 Zoom 账户前完成应用审核及对应授权验证。
- 正式上线前接入真实登录、工作区成员权限与场次授权；开发身份接口不得暴露公网。

### P4：RTMS、实时转写与 AI（后续独立计划）

采用 `Zoom RTMS → 后端采集服务 → 转写/AI 处理 → SSE 或 WebSocket → 当前侧栏`，不使用 Meeting SDK 伪装机器人或直接抓取参会媒体。

RTMS 可提供音视频、带说话人信息的转写及事件，需要账户具有 Developer Pack credits；实际权限、语言质量、延迟和成本需要专项验证。[RTMS 官方说明](https://developers.zoom.us/docs/rtms/meetings/)

该阶段单独处理告知同意、停止采集、说话人身份对应、数据保留与删除。音视频参会、云录制、实时采集、转写和 AI 应分别建模，不共用当前 `rec` 开关。AI 不可用时真人会议仍应继续。

## 6. 拟定接口与数据

### P1 开发专用接口

`POST /api/meetings/dev/join-config`

- 仅开发身份且显式开启 PoC 时可调用；生产环境不注册或拒绝访问。
- 不接受前端传入的会议号、主持人角色、工作区 ID。
- 返回配置会议的 `meetingNumber`、`password`、`displayName`、`signature`、`expiresAt`。
- 名字仅用于显示，不作为授权依据；签名与密码不写日志、URL 或 localStorage。
- SDK JWT 遵循所选版本规定的有效期，通过 API 鉴权、会议绑定与限流控制发放，不声称单次可撤销。

建议后端配置名：`ZOOM_MEETING_SDK_CLIENT_ID`、`ZOOM_MEETING_SDK_CLIENT_SECRET`、`ZOOM_DEV_MEETING_NUMBER`、`ZOOM_DEV_MEETING_PASSWORD`、`ZOOM_DEV_ENABLED`。这些是本项目拟定名称，不是 SDK 自动识别的变量。

### P2 业务接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/interview-sessions/:id` | 查询有权访问的场次、项目摘要及业务状态 |
| `POST /api/interview-sessions/:id/join-config` | 服务端核验会议绑定、当前用户、场次状态后发放凭证 |
| `GET /api/interview-sessions/:id/notes` | 读取当前作者笔记与版本 |
| `PUT /api/interview-sessions/:id/notes` | 提交文本和版本，冲突返回 409 |
| `POST /api/interview-sessions/:id/complete` | 校验权限并幂等完成场次，不代替 Zoom 全员结束 |

最小数据模型：

- `InterviewRound`：`id / projectId / title / ordinal`。
- `InterviewSession`：`id / roundId / status / meetingNumber / providerAccountId / createdBy / completedAt`；会议密码加密保存，列表不返回。
- `InterviewSessionNote`：`sessionId / authorId / content / version / updatedAt`，场次与作者联合唯一。
- 工作区由关联的 Project 校验；后续会议实例 UUID 与会议号分开存储，不能只凭可重复使用的会议号关联回调。

## 7. SDK 生命周期与状态处理

前端连接状态：`idle → loading → joining → joined → leaving → left`，另设 `error / reconnecting`；等待主持人、等待室等状态按所选 SDK 实际事件映射。

- SDK 动态导入，仅实时面试入口加载，不扩大其他页面的首次加载成本。
- 用户点击后加入，不因页面渲染自动申请媒体权限。
- React StrictMode、重复点击、快速切页时不得重复初始化或重复加入。
- 卸载时取消未完成任务、注销事件、离会并销毁客户端；避免旧异步回调重新写入页面。
- SDK 实例放在组件或 hook 的 ref 中，不放全局 Store。
- 使用 SDK 原生会议控制区，不用无对应能力的自定义按钮模拟成功。
- 固定容器尺寸并按 SDK 能力处理 resize，防止视频与侧栏、共享屏幕、弹出面板相互覆盖。
- 个人离会、网络断线、主持人结束会议、业务完成是不同事件，分别处理。
- 计时显示真实加入后的已用时，不冒充会议计划剩余时间。
- 移动端首期提供外部 Zoom 链接，不强行使用桌面 Component View。

## 8. 验证与验收

### 自动化

- 后端：签名字段和角色限制、配置缺失、生产拒绝开发接口、凭证日志脱敏；P2 增加工作区隔离、场次权限、笔记版本冲突和完成幂等测试。
- 前端 mock SDK：初始化/清理、重复点击、权限失败、加入失败、离会与切页、翻译文案、未接通功能不显示成功。
- 浏览器回归：桌面和窄屏截图对比，会议容器不溢出，其他路由可正常访问。
- 构建检查：区分原有失败与新增失败，不以打包通过代替真实设备测试。

### 必须人工双端验证

1. 主持人在客户端启动，HireOS 加入，候选人通过邀请链接加入。
2. 双向声音、视频、静音、摄像头切换及屏幕共享可用。
3. 等待室放行、会议未开始、密码错误、浏览器拒绝设备权限有可理解的反馈。
4. 断网重连、主持人结束、面试官离会、关闭页面后的媒体释放符合预期。
5. 在实际使用网络、目标浏览器及第二台设备测试，不以单机本地预览作为验收。
6. 真实模式不存在示例转写、假录制、假保存、自动评分或未经确认的场次完成。

没有 Zoom 凭据或第二台设备时，只能报告代码和模拟测试结果，真实会议验收保持待完成。
