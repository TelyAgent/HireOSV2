## Implementation

- All outcomes and next-step targets require a current completed evaluation.
- Requests must carry the reviewed evaluation ID/version and last observed
  decision ID (explicit null for no history). Changed evaluations and decisions
  fail without writes; missing preconditions fail with 400.
- Exact retry is read-only, including the serializable-conflict recovery path.
  It does not complete reopened tasks, create another audit or handoff, or
  treat a withdrawn request as a newly successful decision.
- Withdraw/recreate history is checked against the request's observed decision
  so an old request cannot masquerade as a retry of a later identical decision.
- Responses and reloaded details expose the decision's actual bound evaluation
  ID/version/completion time. Missing historical fields remain null.
- Frontend keeps its reviewed basis in component state, preserves failed input,
  exposes the current application/re-evaluation entry and reload action, and
  sends explicit preconditions. Missing evaluation clears the stale cache.
- F11 PRD includes the approved policy, API errors, retry semantics and rollout.
