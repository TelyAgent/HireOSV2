## Acceptance evidence

- AC-1: New confirmation, cancellation and handoff-request events bind actor,
  timestamp and exact package version. Snapshot/event and operation commit in one
  serializable transaction. Audit insertion failure rolls everything back.
- AC-2: The package page lists events in stable database sequence order, including
  handoff-version HR/HM confirmation times and later cancellation/reconfirmation.
  A known versioned handoff followed by changed confirmation is not described as
  proof that the original handoff bypassed checks. Missing historical logs are
  explicitly unavailable, never reconstructed from current timestamps.
- AC-3: Isolated PostgreSQL tests create a fresh task, confirm HR, reject handoff
  without HM (no handoff event), confirm HM, then send. The handoff references the
  same snapshot containing both confirmations and occurs after both timestamps.
  Tests also prove later reconfirmation preserves the original snapshot/event,
  foreign-workspace history returns 404, and an injected event-write failure
  rolls back task changes and snapshot creation.

and reliable downstream invalidation delivery (#319) remain unimplemented.

record is revoked or rewritten. Migration and API/rollback documentation:
