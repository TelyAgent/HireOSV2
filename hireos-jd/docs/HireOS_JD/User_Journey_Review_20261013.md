# JD Management User Journey 审查报告

审查对象：`docs/product/JD_Management/HireOS_Command_JD_Management_Role_User_Journeys_v1.0.md`  
审查依据：2026-10-13 JD Management 评审会议转写总结、JD Management PRD/Interface Spec/Design Brief v1.3  
审查结果版本：User Journey v1.1

## 1. 总体结论

原 v1.0 已覆盖会议要求的主体结构，尤其是 HR、面试官、管理者三类角色的登录目的、操作路径、关注点、权限边界、角色交接以及 AI 审查 YAML 输入格式。因此它已经不是单纯的页面功能列表，而是一份可用于角色审查的 User Journey 基线。

但对照会议记录，原 v1.0 仍有五类不足：

1. 没有把市场薪资调研作为创建 JD 的核心闭环；
2. 没有明确“对内对外、仅内部、restricted”三类信息的完整规则；
3. 对截止时间、计划发布时间、逾期和待谁处理的描述不够硬；
4. 没有把编辑、招聘问答、市场调研三种交互模式的切换写成强制要求；
5. 应用性检查虽然有一般性问题清单，但没有作为每次 Review 必须执行的硬性门槛。

以上缺口已补入 User Journey v1.1。

## 2. 要求对照矩阵

| 会议要求 | v1.0 状态 | v1.1 处理 |
|---|---|---|
| 明确角色是谁 | 已覆盖 | 保留 HR、面试官、管理者映射，并补充管理者不是超级权限角色 |
| 明确登录目的 | 已覆盖 | 保留每个角色的登录后问题清单 |
| 明确登录入口/页面 | 已覆盖 | 保留 Home、My Tasks、Job Library、Job Workspace、Approval 等路径 |
| 明确角色核心操作 | 已覆盖 | 保留逐阶段路径，并补充待我处理、截止时间和发布目标 |
| 明确角色关注点 | 已覆盖 | 增加预算、发布时限、市场调研、状态和下一步 |
| 明确内部/外部/restricted 信息 | 部分覆盖 | 新增信息可见性分层、读写/确认/发布/AI 使用规则 |
| 支持招聘市场调研 | 缺失 | 新增无须选中文字即可问答、来源/日期、人工确认和写回薪资的要求 |

| 失败、超时、权限撤销恢复 | 已覆盖 | 补充到应用性硬性检查和角色成功标准 |

## 3. v1.1 新增的关键要求

### 3.1 业务信息闭环

创建职位不再只被描述为“生成 JD”，而是必须完成：

```text
招聘问题/市场调研
→ 来源和日期明确的参考
→ 人工确认内部预算
→ 形成公开薪资表达
→ 生成 Internal JD / External JD
→ 按权限确认、审批和发布
```

### 3.2 角色化首页

审查时必须检查用户一登录是否能看到与角色相关的事项：

- HR：待补全、待审批、待发布、交付失败；
- 管理者：待我确认、待我审批、急需发布、已逾期；
- 面试官：我的面试任务、采用的 snapshot、待补充证据和 needs_refresh。

### 3.3 应用性硬门槛

Review 不仅检查功能是否存在，还必须检查：

- 用户是否知道自己当前处于哪种模式；
- 能否一步完成的操作是否被拆成多步；
- 是否需要重复输入或重复跳转；
- 当前页面是否提供足够的下一步提示；
- 角色是否只看到与其目标和权限相关的信息。

## 4. 仍需产品确认的问题

User Journey 已明确将以下问题标为 `open_questions`，实现前不能擅自假设：

- 审批超时自动生效是 24 小时还是 48 小时；
- 自动生效适用哪些审批流；
- 薪资调研数据源和引用规则；
- 调研结果是否可自动写入预算字段；
- 面试官是只评论/建议，还是可编辑某些字段；
- JD 完成截止时间和计划发布时间是否分开；
- 已招到人/关闭状态由哪个模块维护。

## 5. 审查结论

原 v1.0 的结构方向正确，但不足以完整反映会议提出的业务和应用性要求。更新后的 v1.1 可作为 AI Review 的角色输入，但在正式实现前仍需补齐上节的产品决策，并将这些决策同步到 PRD、Interface Spec 和权限契约。
