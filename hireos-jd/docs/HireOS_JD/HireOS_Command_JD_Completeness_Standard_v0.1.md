# HireOS Command — JD 完整性标准（AI 检查依据）

Doc ID: CMD-JD-CHK-001  
Version: v0.1  
Scope: JD Management · 创建 / 编辑 / 提交审批 / 发布前的完整性与质量检查  
用途: AI 逐项核对一份 JD 是否完整，并给出缺失项、质量问题和修改建议。

---

## 1. 如何使用这份标准

### 1.1 两种级别

| 级别 | 含义 | 缺失时的处理 |
| --- | --- | --- |
| **必填 Required** | 没有它 JD 就无法用于招聘、筛选或评估 | 判定为"不完整"，阻止提交审批 / 发布 |
| **选填 Optional** | 能提升 JD 质量，但缺失不影响使用 | 只给出"建议补充"，不阻止流程 |

### 1.2 单项判定结果

| 状态 | 含义 |
| --- | --- |
| **Pass** | 内容存在，且满足"完整标准" |
| **Weak** | 内容存在，但命中"常见缺陷"（模糊、不可验证、自相矛盾等） |
| **Missing** | 必填项没有内容 |

必填项为 Weak 时，按"待修改"处理，不等同于缺失，但同样需要修复后才能发布。

### 1.3 内容分级（每个内容块必须有一个）

| 分级 | 含义 | 典型内容 |
| --- | --- | --- |
| **Public 对外公开** | 展示在对外职位页和渠道 | 职位名、职责、要求、公开薪资范围 |
| **Internal 内部可见** | 有该职位访问权限的人可见 | 汇报对象、团队结构、业务背景 |
| **Confidential 保密** | 不对外，不交给 AI 改写，仅限指定人员 | 内部薪资上限、替换某人的原因 |

### 1.4 整体结论

| 结论 | 条件 |
| --- | --- |
| **Ready 可提交** | 所有必填项 Pass，没有合规阻断项 |
| **Needs work 待完善** | 无 Missing，但存在 Weak，或选填项缺失较多 |
| **Blocked 阻断** | 存在必填的 Missing，或存在合规阻断项（见第 4 节） |

## 2. 检查清单

> "建议分级"是该内容块默认应该打上的可见范围，AI 需要核对内容与分级是否匹配（见第 3 节）。

### A. 基本信息

| ID | 内容 | 级别 | 建议分级 | 完整标准 | 常见缺陷 |
| --- | --- | --- | --- | --- | --- |
| A1 | 职位名称 Job title | 必填 | Public | 具体、可搜索，包含职能 + 资历（如 Senior Backend Engineer），不超过 60 字 | 含内部编号 / 代号；只有资历没有职能；"Ninja""Rockstar"等营销词 |
| A2 | 部门 Department | 选填 | Internal | 对应组织架构里存在的部门 | 与职位名明显不符 |
| A3 | 团队 Team | 选填 | Internal | 说明所在小组 | — |
| A4 | 资历级别 Level | 必填 | Public | 与职位名、经验年限一致（Junior / Mid / Senior / Lead / Manager / Director） | 级别与经验要求矛盾（如 Junior 要求 8 年经验） |
| A5 | 雇佣类型 Employment type | 选填 | Public | Full-time / Part-time / Contract / Intern 之一 | — |
| A6 | 工作方式 Workplace type | 选填 | Public | On-site / Hybrid / Remote 之一 | 与地点描述冲突（标 Remote 却要求每天到岗） |
| A7 | 工作地点 Location | 必填 | Public | 城市 + 国家；Remote 需写明可接受的地区 / 时区 | 只写国家；Remote 没有地区限制说明 |
| A8 | 招聘人数 Headcount | 必填 | Internal | 大于等于 1 的整数 | 缺失；为 0 或小数 |
| A9 | 用人经理 Hiring manager | 选填 | Internal | 系统内真实用户 | — |
| A10 | 招聘负责人 Recruiter | 选填 | Internal | 系统内真实用户 | — |
| A11 | 汇报对象 Reports to | 选填 | Internal | 具体职位或人 | 写"待定"且没有说明何时确定 |
| A12 | 招聘原因 Hiring reason | 选填 | Internal | 新增编制 / 业务扩张 / 替换 三选一 | — |
| A13 | 替换对象及原因 Replacement detail | 选填（若招聘原因为"替换"，建议补充） | Confidential | 说明替换谁、原因、是否可告知团队 | 出现在 Public / Internal 块里 |
| A14 | 优先级 Priority | 选填 | Internal | Low / Normal / High / Urgent | — |
| A15 | 期望到岗日期 Target start date | 选填 | Internal | 具体日期或区间 | — |
| A16 | 申请截止日期 Application deadline | 选填 | Public | 具体日期 | 已过期仍在发布 |

### B. 职位概述

| ID | 内容 | 级别 | 建议分级 | 完整标准 | 常见缺陷 |
| --- | --- | --- | --- | --- | --- |
| B1 | 职位概述 Role summary | 必填 | Public | 2–4 句，说明这个职位做什么、为谁做、价值是什么 | 只有一句空话；把职责清单重复一遍；出现内部敏感信息 |
| B2 | 业务背景 Business problem | 选填 | Internal | 说明这个职位要解决什么业务问题、为什么现在招 | 缺失；只写"扩大团队" |
| B3 | 公司 / 团队介绍 About us | 选填 | Public | 1–3 句公司或团队介绍 | 与官网口径不一致 |
| B4 | 协作关系 Collaborators | 选填 | Internal | 主要协作的团队与角色 | — |

### C. 职责与目标

| ID | 内容 | 级别 | 建议分级 | 完整标准 | 常见缺陷 |
| --- | --- | --- | --- | --- | --- |
| C1 | 核心职责 Responsibilities | 必填 | Public | 3–8 条，以动词开头，每条一件事，可观察 | 少于 3 条；以"负责"开头却没有对象；一条里塞多件事；全是形容词 |
| C2 | 预期成果 Expected outcomes | 选填 | Internal | 说明期望达成什么目标（可量化更好） | 缺失；"做好工作""提升效率"之类无法衡量 |
| C3 | 入职成功标准 Success criteria | 选填 | Internal | 至少给出 30 天 / 90 天 / 6 个月中的两个阶段 | 缺失；只有一个阶段；与职责无关 |
| C4 | 关键交付物 Key deliverables | 选填 | Internal | 列出主要产出物 | — |

### D. 任职要求

| ID | 内容 | 级别 | 建议分级 | 完整标准 | 常见缺陷 |
| --- | --- | --- | --- | --- | --- |
| D1 | 任职要求 Requirements | 必填 | Public | 3–8 条，每条单一、可验证、与职责对应；其中至少 2 项为具体技能或工具，并说明熟练程度 | 少于 3 条；"沟通能力强"这类无法验证；一条里混了多个标准；与职责无关；只写通用词（"熟悉办公软件"） |
| D3 | 经验年限与领域 Experience | 选填 | Public | 给出年限 + 领域，与级别 A4 一致 | 只有年限没有领域；与级别矛盾 |
| D4 | 工作授权 / 资格 Work authorization | 选填 | Public | 明确所需的工作许可 / 身份 | 缺失；写成了国籍歧视（见第 4 节） |
| D5 | 学历 / 证书 Education & certification | 选填 | Public | 写明名称，并区分"必须"还是"优先" | 把非硬性资质写成必须 |
| D6 | 语言要求 Languages | 选填 | Public | 语言 + 听说读写水平 | 只写"英语好" |
| D7 | 加分项 Nice-to-have | 选填 | Public | 0–5 条，明确标注为"优先" | 与必备要求混在一起 |
| D8 | 软技能 Soft skills | 选填 | Public | 附带行为证据要求 | 只有形容词 |
| D9 | 工作安排要求 Work arrangement | 选填 | Public | 如时区重叠、出差比例、值班 | 与 A6 冲突 |

### F. 薪酬与福利

| ID | 内容 | 级别 | 建议分级 | 完整标准 | 常见缺陷 |
| --- | --- | --- | --- | --- | --- |
| F1 | 对外薪资范围 Public salary range | 选填 | Public | 最小值 + 最大值 + 币种 + 周期（月 / 年）+ 税前 / 税后 | 只写"面议"；缺币种或周期；上限明显高于内部预算 |
| F2 | 内部预算上限 Internal ceiling | 选填 | Confidential | 数值 + 币种 + 周期，且不低于对外范围的上限 | 出现在 Public 块里；低于对外范围下限 |
| F4 | 奖金 / 股权 Bonus & equity | 选填 | Public 或 Internal | 说明类型与大致范围 | 把保密的股权方案写进 Public |
| F5 | 福利概述 Benefits | 选填 | Public | 3–6 条主要福利 | — |

### I. 分级、版本与发布

| ID | 内容 | 级别 | 建议分级 | 完整标准 | 常见缺陷 |
| --- | --- | --- | --- | --- | --- |
| I1 | 每个内容块都有可见范围 Visibility level | 必填 | — | 所有块都已标为 Public / Internal / Confidential | 有块未标记 |
| I2 | JD 唯一 ID JD ID | 必填（系统自动生成） | — | 格式 JD-年份-编号，全局唯一 | — |
| I6 | 版本说明 Version note | 选填 | Internal | 一句话说明本次改了什么、为什么 | — |
| I7 | 语言版本 Language | 必填 | Public | 标明 JD 使用的语言；多语言版本内容一致 | 多语言版本的薪资、要求不一致 |

## 3. 跨项一致性检查（AI 必须做）

| 编号 | 检查 | 不通过时的处理 |
| --- | --- | --- |
| X1 | 级别与经验年限一致（A4 与 D3） | Weak，指出矛盾 |
| X2 | 工作方式与地点、工作安排一致（A6、A7、D9） | Weak |
| X3 | 每条必备要求（D1）能在职责（C1）里找到对应工作内容 | Weak，列出没有对应职责的要求 |
| X4 | 每条职责（C1）至少被一条要求或加分项覆盖 | 建议补充 |
| X5 | 内部预算上限不低于对外薪资范围上限（F1、F2） | Weak |
| X6 | 对外薪资范围与级别匹配（F1、A4） | 建议复核 |
| X7 | 同一份 JD 内，职位名、级别、地点、薪资在各处写法一致 | Weak |
| X8 | 多语言版本的关键事实一致（I7） | Weak |

## 4. 分级与合规检查（AI 必须做）

### 4.1 分级匹配

| 编号 | 规则 | 不通过时的处理 |
| --- | --- | --- |
| V1 | Confidential 内容（F2、A13）不得出现在 Public 或 Internal 块里 | **阻断** |
| V2 | Public 块不得出现：内部预算、替换原因、内部人员评价 | **阻断** |
| V3 | Internal 块里出现可对外公开的内容时，提示"是否应改为 Public" | 建议 |
| V4 | 没有分级的块（I1） | **阻断** |
| V5 | 标为 Confidential 的块，不发送给 AI 做改写或总结 | 系统规则 |

### 4.2 合规

| 编号 | 规则 | 不通过时的处理 |
| --- | --- | --- |
| R1 | 要求中不得以年龄、性别、婚育状况、民族、宗教、健康状况作为条件，除非有合法依据 | **阻断** |
| R2 | 国籍相关表述只能写成"需要在某地合法工作"，不得写成"仅限某国人" | **阻断** |
| R3 | 不使用带有性别或年龄暗示的措辞（如 "young and energetic"、"salesman"） | Weak |

## 5. 语言与质量规则

| 规则 | 说明 |
| --- | --- |
| 可验证 | 每条要求都应能通过简历、作品或作答判断是否满足；"沟通能力强""学习能力强""抗压"这类词，必须补充具体表现 |
| 单一 | 一条要求只写一个标准，不要用"且 / 以及 / 或"把多个标准串在一起 |
| 动词开头 | 职责用动词开头（设计、搭建、推动、分析），避免"负责相关工作" |
| 去营销词 | 不使用 Rockstar、Ninja、Guru 等词；形容词需有事实支撑 |
| 长度 | 对外 JD 全文建议 300–700 词；职责 3–8 条；必备要求 3–8 条；加分项不超过 5 条 |
| 中性措辞 | 使用 "they / 你" 等中性表达，避免性别指代 |
| 区分必须与优先 | 硬性门槛放在必备要求，其余放在加分项，两者不得混写 |

## 6. AI 输出格式（建议）

```json
{
  "jdId": "JD-2026-0102",
  "verdict": "needs_work",
  "summary": { "required": {"total": 10, "pass": 7, "weak": 2, "missing": 1},
               "optional": {"total": 30, "present": 9} },
  "items": [
    { "id": "D1", "status": "weak", "severity": "warning",
      "evidence": "Must have strong communication skills.",
      "reason": "无法验证；没有说明什么表现算满足",
      "suggestion": "改为：能把技术方案写成评审文档，并在跨团队评审中说明取舍（附一个具体例子）",
      "blockId": "b6d" }
  ],
  "complianceFlags": [],
  "visibilityFlags": [
    { "rule": "V1", "blockId": "b10", "from": "internal", "should_be": "confidential" }
  ]
}
```

约定：
- `status`：pass / weak / missing。
- `severity`：blocker（阻断）/ warning（待修改）/ suggestion（建议）。
- `blockId`：指向编辑器里的内容块，方便前端定位到具体位置。
- AI 不得读取、总结或改写被标为 Confidential 的块的正文，只能检查"它是否存在、是否被正确分级"。
