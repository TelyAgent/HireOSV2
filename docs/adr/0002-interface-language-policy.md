# 界面语言：账号级单一偏好

## Context

Identity、JD、Screening、Interview、Written 五个前端原来各用一个 localStorage key 保存界面语言，互不同步；登录页切换语言只写本地；验证码邮件优先使用账号语言，因此已有中文账号在登录页切到英文后，仍会收到中文验证码。Owner 在 #233 确认了下面的规则。

## Decision

| 场景 | 规则 |
|---|---|
| 作用范围 | 界面语言属于账号，五个模块共用一个偏好（Identity `User.locale`）。 |
| 登录前（访客） | 登录页使用本浏览器记住的语言，没有记录时按浏览器语言。 |
| 登录时 | 账号还没有选过语言（`User.localeSetAt` 为空）时，采用登录页当时的语言；已经选过的，保持账号的语言。 |
| 登录后 | 各模块以账号语言为准，覆盖本浏览器记住的语言；在任一模块切换语言，都会写回账号（`PATCH /auth/me`）。 |
| 跨设备 / 清空浏览器存储 | 登录后恢复账号语言。 |
| 验证码邮件 | 使用登录页当前显示的语言（用户此刻能读懂的语言）；没有提供时，使用账号语言。 |
| 候选人 | 候选人沟通语言（笔试邀请、候选人页面等）与 HR 界面语言无关，按 #229 在发送时单独选择。 |
| 文档内容 | JD、题目等文档内容的语言跟随文档本身，不随界面语言改变（#232）。 |

实现：Identity 后端 `auth.service.ts`（`signIn`、`requestCode`）与 `auth.controller.ts`（`PATCH me`）；各模块前端 `src/lib/session.tsx` 中的 `useAccountLocale`。

## Consequences

- 账号在一个模块切换语言后，其他模块要在下次加载时才跟随，不做实时推送。
- 本次升级前创建的账号 `localeSetAt` 为空（默认中文，但视为"未选择"），升级后第一次登录、或第一次打开任一模块时，会采用登录页或该模块当时的语言。
- 演示模式（未登录、不要求登录）下不读写账号，仍只使用本浏览器记住的语言。

## Alternatives

- 每个模块各自记住语言：已否决，跨模块会出现语言不一致。
- 验证码邮件始终使用账号语言：已否决，用户在登录页切换语言后，可能收到读不懂的邮件。
