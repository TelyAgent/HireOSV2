HireOS Interview – Zoom Integration Security Overview

[Company legal name] · Version 1.0 · [Date]

This document describes how the HireOS Interview Zoom app handles Zoom data and how that data is protected. It covers only the Zoom integration: OAuth authorization, interview meetings, the embedded Meeting SDK and Realtime Media Streams (RTMS) transcripts.

1. Purpose of the integration

Interviewers connect their own Zoom account to HireOS. HireOS creates the interview meeting on that account, lets the interviewer host it inside HireOS through the Zoom Meeting SDK, and receives a live transcript of the meeting through RTMS. The transcript is used by the hiring team to review the interview.

3. Security controls

AreaControl
TransportAll traffic to HireOS uses HTTPS (TLS, Let's Encrypt certificate). All calls to Zoom and OpenAI use HTTPS/TLS, and RTMS media connections use TLS.
OAuthAuthorization code flow with a single-use, random state value (expires after 5 minutes) to prevent CSRF. The redirect URI is fixed in configuration. Tokens are refreshed automatically and stored encrypted.
Token encryptionTokens and the Zoom user profile are encrypted with AES-256-GCM. The encryption key is a random 256-bit key stored separately from the data, in a file readable only by the service (permissions 0600).
Webhook verificationEvery webhook is verified with the x-zm-signature HMAC-SHA256 signature and timestamp, using a constant-time comparison, before it is processed. The endpoint.url_validation challenge is answered as documented by Zoom.
Meeting SDKSDK signatures are generated on the server (HS256, 30-minute expiry) and rate-limited. The SDK secret and client secret are never sent to the browser.
Least privilegeOnly the scopes needed for the features above are requested. RTMS is started only with the "start" action, only for meetings HireOS created.
Secrets managementThe Zoom client secret, webhook secret token, OpenAI API key and database credentials are stored in environment files on the server. They are not in the source repository or the container images.
Network isolationThe application runs in Docker containers on a Linux server in Google Cloud. PostgreSQL and the internal services are reachable only inside the private Docker network; only the HTTPS entry point is public.

4. Third-party processing

Transcript text and the interview's evaluation rubric are sent to the OpenAI API (api.openai.com) to draft an interview summary and rubric scores. A person reviews the drafts before they are used. Zoom OAuth tokens, credentials and audio are never sent to OpenAI. OpenAI processes this data under its API terms.
