# M10 Agent 六项产品口径与验收判据

版本：v1.0 / 2026-10-15。依据：用户在 2026-10-15 对 M10 PRD §10 第 2–7 项给出的推荐口径。本文定义已确认的行为方向；表内标为“上线参数待定”的值不能由 Agent 或测试自行猜定。市场薪资调研优先级（原 §10 第 1 项）不在本次六项决定范围内。

## 2. 薪资数据与企业分层

**规则**：薪资调研只使用获授权且能记录来源元数据的数据源。每条数值结论须绑定职位、职级、地区、薪酬口径、采集日期、样本量与换算方法。企业分层使用有版本的配置，条件明确到员工数、发展阶段等；信息不足时显示“未分类”，不由模型猜测“大厂”。来源超过批准的有效期、样本不足或口径冲突时，结果标为“证据不足”，不生成精确 P25/P50/P75。仍可展示已取得的原始来源及其局限，不能包装成可信市场分位数。

**界面**：薪资卡逐条显示来源名称/链接、采集日期、样本量或“未知”、适用画像、口径、换算说明及企业分层配置版本。证据不足时展示原因和可用来源，不显示精确分位数。

**通过判据**：用已授权/未授权、有效/过期、样本充足/不足、口径一致/冲突及企业无法分类的可控数据分别验收；检查 UI、API 与结果记录。任一必要元数据缺失或来源失效时，不得产生精确分位数；“未分类”不能被默认为大厂或中小公司。

**上线参数待定**：具体数据源、分层阈值、样本下限、有效期和引用规则由产品批准后版本化。配置未批准前，依赖这些参数的精确市场数字用例应标为 known gap，不得以任意阈值判通过。

## 3. 对标 JD 与公司画像

**规则**：只读取获准使用的对标来源，保留链接、读取时间和来源状态。当前“Agent 草稿快速确认”只围绕“来做什么事”和“行业经验是否覆盖”呈现结构化差异；改进建议须为原创，不把外部公司事实写入我方 JD。公开可见不等于允许长期保存或复制全文。

**公司画像**：建议由 Workspace Admin 管理配置与权限，HR/品牌负责人确认业务内容。每条资料记录负责人、更新时间、确认状态和版本。未确认或过期资料不能被表述为我方薪资、福利、文化或政策承诺。

**通过判据**：成功来源显示链接、时间、状态与两项对标依据；404、登录限制、未授权来源不生成虚构差异。用已确认/未确认的公司资料验证：只有已确认资料可作我方事实，提案不大段复制对标原文。

**上线参数待定**：可用站点/数据商、引用长度、缓存期限、相似度复核规则由产品与法务定稿。公司画像中的具体内容负责人由工作区落实；未落实时该字段保持待确认。

## 4. 意图识别与界面模式

**规则**：Agent 自动识别问答、澄清、改写、调研、操作请求或越界意图，并在输入区显示识别模式和上下文范围。用户可在发送前改选模式，也可在结果上纠正后重新处理原输入。纠正模式不应重复已执行的写入。

| 模式 | 可见结果 | 不应出现 |
| --- | --- | --- |
| 问答/解释 | 回答及依据 | Apply/采纳、文档改动 |
| 生成/改写 | 提案、前后 diff、用户确认入口 | 未确认即写入或声称已写入 |
| 调研 | 带来源及证据状态的结果卡 | 无来源的确定数值、写入成功提示 |
| 高影响操作 | 流程说明、前置条件和有权页面入口 | Agent 代为审批/发布/改权限 |

**通过判据**：同一输入分别触发四类模式，检查模式标签、上下文、控件和 API/DB 副作用。将问答误识别为改写后，用户纠正为问答，应只保留回答，不出现可采纳提案；纠正后不重复写入。

## 5. Finance 与 Workspace Admin 问题

**规则**：F-xx、A-xx 是问题清单分类，不自动给提问者 Finance 或 Admin 权限。Agent 每次以当前用户的业务角色、职位范围、字段授权和 Workspace AI 政策判断。Finance 的 HC/预算问题，有权时可给获授权的数值、依据与审批入口；Agent 不代作预算决定。Admin 的设置/审计问题可解释现状并引导共享设置页；改权限、模型预算或策略须在有权限的设置操作中完成。无权时说明原因和下一步，不泄露受限值。

**通过判据**：同一 F-02/F-03 与 A-03/A-13 问题分别以有权、无权身份执行；检查模型输入、UI 和 API 响应的字段过滤。仅凭问题中自称 Finance/Admin 不得扩大权限；Agent 回复不得直接修改预算或设置。

**待确认**：Finance 是否成为独立业务角色，以及 F-01～F-10、A-01～A-15 每题的预期处理类别。全量题目回归在逐题标注表批准前不得宣称完成。

## 6. Agent 创建默认值

**规则**：若产品允许预填 Ho Chi Minh City, VN、Headcount 1、Hybrid，必须在界面和创建/保存前摘要逐项标为“系统默认·待确认”，记录来源与确认状态。用户未确认前，Agent 不把这些值写成正式 JD 事实；在必填与审批检查中按未确认处理。用户明确输入的值优先于默认值。

**通过判据**：只给职位名创建、用户明确指定不同值、用户确认默认、用户拒绝默认四种用例分别检查展示、摘要、保存内容和 M6 门禁；未确认默认不得作为已确认事实出现在正式 JD。三版草稿中的默认来源与状态须一致。

**上线参数待定**：产品批准哪些字段允许预填、哪些必须留空追问，以及如何在保存时确认必填默认；未批准字段不得由 Agent 自行发明默认值。

## 7. 权限模型与审批

**已定方向**：采用 Recruiter / TA、Hiring Manager、HR Approver、Viewer 四个业务角色，并恢复审批。Super Admin / Workspace Admin 是设置管理能力，不替代业务角色，也不因管理员身份自动获得受限字段读取、审批或发布权。Agent 的有效权限取当前用户角色、职位范围、字段授权、Workspace AI 政策与工具白名单的交集，执行时重新校验。

| 业务角色 | 读取 | 生成提案 | 采纳/保存 | 提审 | 批准 | 发布 |
| --- | --- | --- | --- | --- | --- | --- |
| Recruiter / TA | 授权职位与字段 | 可 | 授权字段，可显式确认 | Ready 且有职位权限时可 | 不可 | 审批有效且有发布权限时可 |
| Hiring Manager | 授权职位与字段 | 可 | 仅授权字段 | 不可 | 不可 | 不可 |
| HR Approver | 待审/授权职位与字段 | 可建议 | 仅明确授权字段 | 不可 | 对本人可审的冻结版本可 | 不可 |
| Viewer | 仅授权内容 | 可问答，不生成可应用提案 | 不可 | 不可 | 不可 | 不可 |

以上矩阵是默认业务动作边界；预算、HC、Confidential/restricted、跨职位访问等逐字段权限仍由产品/M7 确认。Admin 能分配业务角色或配置设置，不等于能看到这些字段或代替 HR Approver 批准。

**通过判据**：同一问题/操作用四角色及带 Admin 身份的用户测试，验证 UI 与服务端一致；撤权后重试须立即拒绝。检查模型输入不含未授权正文、写接口返回拒绝、审批记录的决定者为有权 HR Approver（或 M7 已定义的超时系统事件），绝不是 Agent。

**待确认**：Finance 的角色位置、职位范围分配、预算/HC 等字段的细粒度授权及 AI 使用范围；这些未定项不能由旧三档权限推导。
