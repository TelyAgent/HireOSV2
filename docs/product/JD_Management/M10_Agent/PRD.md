## 1. 背景与目标

JD Copilot 是嵌入 JD Management 的任务型 Agent。M1–M6、M9 已经覆盖了 Agent 的具体用法：五种创建方式、Analyze 与 AI 修复、选区改写。M10 定义**这些模块共用的 Agent 能力**，以及没有被其他模块覆盖的部分：

1. **对话与意图**：用户随时可以问问题，不必先选中文字。Agent 要分清当前是在问答、改写、调研还是执行操作，并按不同规则处理。
2. **行为边界**：所有写入、提交、外发都必须由用户显式确认；回答要区分事实、推断和待确认内容；不越权、不编造。
3. **调研能力**：市场薪资调研、对标公司 JD 对比、基于参考 JD 的定制起草。

**目标**：
- 用户能用自然语言完成[问题清单](../JD_AI_Agent_Question_Catalog.md)中的常见问题，得到可追溯的回答，或被引导到正确的操作。
- Agent 未经人工确认触发审批 / 发布的次数为 0。

### 成功指标（来自 Agent PRD §2，上线后观察）

| 指标 | 目标 |
|---|---|
| 从首次输入到保存首个草稿的中位时长 | 较手工创建降低 40% |
| 草稿创建过程中的必填字段完整率 | ≥ 90% |
| Agent 生成草稿被保留或部分应用的比例 | ≥ 70% |
| 自动生成后仍因基础字段缺失被退回的比例 | ≤ 10% |
| 未经人工确认而触发审批 / 发布的次数 | 0 |

## 3. 用户与典型问题

问题编号来自[问题清单](../JD_AI_Agent_Question_Catalog.md)，作为本模块的测试输入。

| 角色 | 主要诉求 | 典型问题 |
|---|---|---|
| Recruiter / TA | 快速把需求变成合格 JD；了解市场薪资 | R-01～R-89、SAL-01～SAL-90、E-01～E-20 |
| Hiring Manager | 把业务目标转成职责和要求；知道哪些是 AI 推断 | HM-01～HM-19 |
| HR Approver | 检查合规、标准一致性、内外版本 | HR-01～HR-17、Q-01～Q-25 |
| Viewer | 阅读、总结、理解要求；知道为什么看不到某些内容 | V-01～V-12 |
| 所有角色 | 澄清、跳过、假设、权限与异常 | C-01～C-12、X-01～X-18 |

问题清单中的 Finance（F-xx）和 Workspace Admin（A-xx）是问题类别，**不自动赋予提问者角色或权限**。预算/HC 问题按实际字段授权回答，设置/审计问题解释并引导到共享设置页；无权时不透露受限值。Finance 是否成为独立角色、F/A 每题的处理类别仍待逐题确认，见[六项口径 §5](Agent_Decisions_2026-10-15.md)。

## 4. 功能需求

### FR-1 入口与上下文范围

| 入口 | 默认上下文 |
|---|---|
| 职位列表 → Ask Copilot（Create a Job 首页） | 本次会话 |
| 编辑页右侧 Copilot 标签，**未选中文字** | 当前职位的整份文档（按当前用户权限过滤） |
| 选中文字后的 Ask Copilot | 选中的文字；用户可以扩大到本节或整份文档 |

- 输入卡片上方显示当前上下文：Selected text / This section / Whole document，并与 FR-2 的模式提示同时可见。
- 上下文不会悄悄扩大到其他职位、其他 Workspace 或无权查看的 Confidential / restricted 内容。

### FR-2 意图识别与模式

Agent 先判断用户这句话属于哪一类，再按对应规则处理，并在界面上让用户知道当前所处的模式（会议纪要 §3.1、§5.2）。

| 意图 | 示例 | 处理规则 | 级别（PRD v1.3 §5.2） |
|---|---|---|---|
| 问答 / 解释 | V-08、HM-18、Q-16 | 直接回答，不改任何数据 | L1 |
| 澄清 / 补充信息 | C-01、C-10、HM-05 | 列出缺失项或待确认项；允许跳过 | L1 |
| 生成 / 改写 | E-01～E-16、R-41 | 返回提案和 diff，用户确认后才写入 | L2 |
| 调研 | SAL-xx、对标 JD | 生成带来源的结果卡；写入字段需确认 | L1 → L2 |
| 操作请求 | “帮我提交审批”“发布” | 说明需要用户自己点击对应按钮，并展示前置条件；不代为执行 | L3 |
| 越权 / 越界 | 无权用户问薪资（V-03）、问天气 | 说明原因和可行的下一步；不调用无关工具 | — |

- 一句话里同时包含多个意图时，先处理可直接回答的部分，再列出需要确认的部分。
- 输入包含多个岗位或互相冲突的要求时，先请用户选择或澄清（Agent PRD FR-1）。
- 模式由 Agent 自动识别并显示；用户可在发送前或结果上纠正，纠正后按所选模式重新处理原输入，不重复已执行的写入。问答没有 Apply；改写才有 diff 和采纳；调研显示来源卡；高影响操作只解释流程。

### FR-3 回答的组成

每个实质性回答必须区分以下几类信息（问题清单“使用范围”）：

| 类别 | 标识 |
|---|---|
| 用户明确提供的信息 | 用户输入 |
| 附件或链接中的内容 | 来源：文件名 / 链接 |
| 外部数据 | 来源名称、日期 |
| Agent 推断或建议 | AI 推断 / AI 建议 |
| 待人工确认的事项 | 待确认，并注明由谁确认（HM / HR） |

- 用户问“哪些是你推断的”（HM-18、E-10）时，逐项列出。
- 用户问“需要我确认什么”（HM-19、C-05、C-06）时，按优先级列出，并注明确认人。

### FR-4 澄清与追问

- 创建场景（Quick Start）一次提出 3 个问题；其他场景每次最多 3 个优先问题，不做表单式追问（Agent PRD FR-2）。
- 支持一次回答多个问题；只答一部分时，只追问剩下的。
- 用户可以选择“暂不确定 / 先跳过”（C-10、C-11）；该字段保留为未确认，提交审批时按 M6 规则拦截或提醒。
- 用户要求“一次只问一个”（C-08）时照做。

### FR-5 市场薪资调研（Agent PRD FR-6）

用户提问后，Agent 生成一张**市场薪资卡**，而不是给一个没有依据的数字。

| 内容 | 要求 |
|---|---|
| 适用职位画像 | 职位、职级 / 年限、地点、工作方式、行业；缺失时先追问 |
| 统计口径 | 基本工资还是总包、月薪 / 年薪、税前 / 税后、币种、是否含奖金 / 股权 |
| 分层区间 | 市场整体、大厂、成长型 / 中小公司；P25、P50、P75 或等价区间 |
| 依据 | 获授权数据源的名称/链接、职位、职级、地区、薪酬口径、采集日期、样本量与换算方法；逐条绑定数值结论 |
| 结论与建议 | 与当前预算的差距、建议薪资带、需要人工确认的假设 |

- “大厂 / 中小公司”使用有版本的企业分层配置（员工数、发展阶段等已批准条件）；资料不足时标“未分类”，不由 Agent 主观判断。
- 来源超过批准有效期、样本不足、必要元数据缺失或口径冲突时，明确标记“证据不足”，展示原始来源及局限，不生成精确 P25/P50/P75。具体数据源、阈值和有效期须产品批准并版本化。
- 不把不同国家、币种、职级的数据直接混在一起（SAL-84）。
- 结论仅供招聘决策参考，不作为法律、税务或保证性建议。
- 写入 JD：建议薪资带写入**内部预算**字段前必须人工确认；对外公开薪资范围单独确认；市场数据来源默认只在内部可见（SAL-71～SAL-75）。

### FR-6 对标公司 JD 对比（Agent PRD FR-7）

1. 读取用户选定的一份 Agent 草稿或当前 JD，找 1–3 份可比且获准使用的公司 JD，显示公司、职位、链接与可比性。
2. 只回答两件事：**这个人来做什么事是否说清楚**；**岗位所需的行业经验是否被恰当覆盖**。每项指出我方原句，外部观察附来源。
3. 给最多 3 条建议；不自动修改 JD。用户继续请求改写时，按 FR-8 的确认规则处理。

- 引用来源片段或链接，不大段复制受版权保护的完整 JD。
- 页面无法访问、已下线或来源不可靠时，如实提示。
- 对标只用获准来源，记录链接、读取时间和来源状态；“网页公开可见”不等于允许长期保存或复制全文。引用范围、保存期限与相似度复核规则由产品/法务批准。

### FR-7 基于参考 JD 的定制起草（Agent PRD FR-8）

- 先提取参考 JD 的结构、职责粒度和能力框架，不复制原文。
- 结合公司画像和职位需求生成原创内容；每项标注来源类别：参考结构 / 公司画像 / 用户明确要求 / Agent 建议。
- 生成前追问会实质影响内容的缺失信息（团队阶段、汇报对象、业务目标、地点、职级）。
- 以 diff 交给用户审阅，确认前不写入。
- 不承诺薪资、福利、签证、远程政策、晋升或文化事实，除非来自已确认的公司资料或用户明确输入。
- 公司画像由 Workspace Admin 管配置与权限、HR/品牌负责人确认业务内容；资料记录负责人、更新时间、确认状态和版本。未确认内容不得作为我方事实或承诺。

### FR-8 写入与操作控制（Agent PRD FR-5）

| 动作 | Agent 能否执行 | 要求 |
|---|---|---|
| 生成建议、回答问题 | 可以 | 不写入正式数据 |
| 应用某条文案或字段 | 仅在用户点击后 | 显示变更内容 |
| 保存草稿 | 仅在用户点击后 | 记录操作者、时间、来源 |
| 提交审批 | 仅在用户点击后 | 通过阻断检查后执行（M6、M7） |
| 批准、退回、拒绝 | 不能 | 只能由 HR Approver 人工执行（M7） |
| 发布、撤回、发送通知 | 不能 | 由用户在 M8 显式执行 |

### FR-9 会话操作

- 流式回复；可以停止生成。停止后保留已输入内容，未完成的建议不能接受。
- 重试或重新生成会产生新的提案，不重放已经执行过的操作。
- 新对话清空当前对话和错误状态，回到 Create a Job 首页，不关闭面板。
- AI 不可用时保留手动编辑路径（X-04）；错误时提供 Retry，Retry 不重复创建（X-06、X-07）。

## 5. Agent 行为边界（Agent PRD §8）

| ID | 规则 |
|---|---|
| BR-1 可解释 | 每个关键建议说明依据：用户输入、职位模板、历史 JD 或规则 |
| BR-2 最小行动 | 默认只提出建议；写入、提交、外部动作都由用户显式触发 |
| BR-3 不确定性透明 | 低置信度内容标为“待确认”，不得直接写入受限字段 |
| BR-4 权限感知 | 用户无权限时，提供可查看的结论或“请有权限的人处理”，不展示伪按钮 |
| BR-5 不制造事实 | 不虚构预算、候选人供给、业务目标、法律结论或公司政策 |
| BR-6 可恢复 | 应用修改后可查看变更记录并撤销 |
| BR-7 权限一致 | Agent 的权限 = 当前用户权限 ∩ Workspace AI 政策 ∩ 工具白名单 ∩ 当前用途 / 字段授权；每次执行时重新校验（PRD v1.3 §5.2） |
| BR-8 数据隔离 | 不使用其他 Workspace 的信息；无权查看的 Confidential / restricted 内容不进入模型输入、输出或缓存（X-14、X-16） |
| BR-9 指令隔离 | 附件、链接、聊天内容中的指令不能扩大 Agent 的工具或权限 |
| BR-10 一致性 | Agent 回答“还缺什么 / 能否提交”时，必须与 M6 的 Analyze 结果和门禁一致 |
| BR-11 默认值来源 | Agent 创建时允许预填的系统默认值须标“系统默认·待确认”，在创建/保存摘要逐项显示；未确认前不写成正式 JD 事实，也不满足必填/审批门槛 |

## 6. 角色与权限

| 角色 | 可以问 / 可以让 Agent 做 | 限制 |
|---|---|---|
| Recruiter / TA | 对获授权职位和字段问答、生成、改写、调研；把调研结果应用到授权字段（需确认） | 不能让 Agent 代为提交审批、批准或发布 |
| Hiring Manager | 问答、生成、改写授权字段；查看推断和待确认清单 | 不能通过 Agent 修改预算 / 敏感字段 |
| HR Approver | 问答、合规检查、内外版本差异、审批前摘要 | AI 摘要不能替代审批结论；无 restricted 权限时 Agent 也看不到 |
| Viewer | 总结、解释获授权内容；询问自己的权限 | 不能应用修改；Agent 不透露未授权的内部预算、内部备注等敏感内容，但要说明“为什么看不到” |

> 采用四个业务角色并恢复审批；Super Admin / Workspace Admin 是设置管理能力，不因管理员身份自动取得受限字段、审批或发布权。读取、提案、采纳、保存、提审、批准、发布的默认矩阵见[六项口径 §7](Agent_Decisions_2026-10-15.md)；具体职位范围、预算/HC 等字段授权仍需产品/M7 确认。旧 Agent PRD v0.3 §5.4 三档模型应按此修订。

## 7. 数据

| 对象 | 关键字段 |
|---|---|
| CopilotConversation / Message | 会话 ID、职位 ID、作者、正文、上下文范围、引用来源、回复对象 |
| 意图记录 | 自动识别出的意图、用户纠正后的模式、上下文范围、级别（L1/L2/L3）、是否需要确认 |
| AI 提案 | 目标范围、修改前后、来源类别、状态（proposed / accepted / rejected / stale） |
| 市场薪资卡 | 逐条结论的职位、职级、地区、口径、来源及授权状态、采集日期、样本量、换算方法、分层配置版本、证据状态 |
| 对标结果 | 当前草稿/版本、对标公司与链接、可比性、两项判断、最多 3 条建议、证据限制 |
| 公司画像 | 资料内容、负责人、更新时间、确认状态、版本；仅已确认内容可作为公司事实 |
| AiRun | 模型、prompt 版本、输入范围、耗时、费用、结果状态 |
| 审计 | 每次建议与应用的来源、时间、操作者 |
