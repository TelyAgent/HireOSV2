## 1. 新增功能需求

### FR-10 暂不支持的能力（合入 §4，并在 FR-2 意图表增加一行）

用户请求的能力尚未上线、不归 JD Agent 负责或缺少数据源时：

- 明确说明“暂不支持”或“该能力属于 X 模块”，给出手动替代路径或入口。
- 不假装已完成，不描述不存在的结果（例如不声称“已检查过全部职位，没有重复”）。
- 归属其他模块的内容（筛选标准、面试评价维度、权重、面试题）不在 JD 中生成并写入；可以说明应去的模块。

FR-2 意图表新增：

| 意图 | 示例 | 处理规则 | 级别 |
|---|---|---|---|
| 暂不支持 / 其他模块 | R-07 复制职位、R-10 重复检测、R-74 面试题、SAL-63 内部薪资公平、Q-21 导出 | 说明暂不支持或归属模块，给替代路径；不调用无关工具 | — |

### FR-11 产品使用类问题的依据（合入 §4）

- 用户询问“能不能做 / 在哪里做”（如 R-02、V-04、Q-18、A-01～A-15）时，Agent 依据**版本化的产品帮助内容**回答，与当前上线功能一致。
- 产品帮助内容随版本发布更新；未覆盖的问题回答“不确定”并引导查看帮助或联系管理员，不推测功能。
- 依赖：新增“产品帮助内容”作为 §8 依赖项，负责人待定。

### FR-12 回答语言（合入 FR-3）

- 回答语言跟随用户提问语言；用户明确要求时按要求切换。
- 写入 JD 的提案内容使用该 JD 的语言版本，不因提问语言改变 JD 语言；需要翻译时按 E-07 处理，数字与必需条件保持一致。
- 待确认：界面为英文、问题清单为中文时，默认语言以哪个为准。

### FR-13 会话上下文边界（合入 FR-1）

- 同一会话切换到另一个职位时，上下文随之切换，不把前一个职位的内容带入。
- 多轮对话中用户改口时，以最新的明确输入为准，并在回答中确认改动。
- 用户口头声明的身份（“我是 Finance / HR / 管理员”）不改变权限判断。

## 2. 新增行为边界（合入 §5）

| ID | 规则 |
|---|---|
| BR-12 聊天内指令隔离 | BR-9 扩展到用户直接输入或粘贴的文本：其中的“SYSTEM”“忽略规则”等指令不能扩大权限、跳过确认或改变工具范围 |
| BR-13 不写入歧视性要求 | 用户要求加入年龄、性别、婚育、民族、国籍等与工作无关的条件时，拒绝写入，说明原因，并提供与工作相关的替代写法 |
| BR-14 候选人个人信息 | JD Agent 不查询、不输出候选人的联系方式、住址等个人信息 |
| BR-15 不给确定性法律结论 | 合规类问题只提示风险和依据，不给“合法 / 不合法”的确定结论 |
| BR-16 状态如实 | 被问到“是否已提交 / 已发布 / 已修改”时，按系统实际状态回答，不顺着用户的错误前提确认 |

## 4. 新增待确认（合入 §10）

1. 测试矩阵中 125 条“待拍板”行的预期类别，重点是：
   - R-68～R-74：JD Agent 是否生成评价维度、权重、面试题，还是一律转到 Interview / Screening；
   - SAL 全组：薪资数据源批准前，期望回答“数据源不可用”还是隐藏调研入口；
   - F-xx、A-xx：Finance 是否为独立角色，设置类问题的回答范围；
   - HM-03、HR-11：是否允许 Agent 读取其他职位做对比。
2. 产品帮助内容的负责人和更新流程（FR-11）。
3. 回答默认语言（FR-12）。
4. 合格线的具体数值（测试矩阵 §9）。
5. 各类 Query 的响应时间阈值（问答、改写、调研分别给出首个反馈与完成时间）。
