## 1. 背景与目标

用户只知道“为什么招、要解决什么问题”，不知道怎么写完整 JD。Quick Start 用三个问题收集招聘意图，由 AI 生成一份结构化草稿；用户审阅并确认建议内容后，点击 Create 创建职位。

**目标**：用户回答三个问题后，得到一份可编辑、逐字段记录来源与确认状态的草稿；对外 JD 与内部资产分开保存和授权查看，并能一键创建职位。

## 2. 范围

| 包含 | 不包含 |
|---|---|
| 三问收集、只追问缺失项；AI 建议职位名并由用户确认 | 生成多个风格版本（属于 M2） |
| 生成 1 份含元数据、对外 5 模块及内部 b/c 资产的草稿，在 Workspace 中审阅 | 跨模块必填项完整性检查和 AI 修复（属于 M6） |
| 查询相似岗位的经验年限，给出带来源的待确认建议 | 薪资市场调研；Create a Job 首页未选择入口时直接输入的分流行为（不纳入本次 M1 验收） |
| 通过对话继续修改草稿 | 提交审批、发布（属于 M7、M8） |
| 文字和语音输入 | |
| 创建职位（draft） | |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-1 | 点击 Quick Start 后，入口标题作为用户消息出现一次，Agent 用**一条消息**同时提出三个问题：为什么招 / 遇到的困难、希望候选人解决什么、必须具备的硬技能 |
| FR-2 | 用户可以一次回答全部或部分问题；三个核心问题中任意一项未获得有效回答时，只追问未回答项，不重复已答内容，且不生成完整 JD。单字 `a` 不视为有效回答 |
| FR-3 | AI 可根据回答提出职位名建议，在草稿中高亮并标记“AI 建议／待确认”；用户须确认或修改后才能 Create。无法提出合理建议时追问 Job title；不使用 `New Role` 或空标题 |
| FR-4 | 三个问题都有有效回答后，显示生成中状态，生成 **1 份**结构化草稿；右侧展开 Workspace，与对话并列 |
| FR-5 | 草稿每个字段记录来源（用户回答 / AI 建议）、版本（Revision）和确认状态（Confirmation Status）；AI 建议在 Workspace 中可识别，待确认内容高亮 |
| FR-6 | 用户在对话中提出修改（如“改为 Remote”），Workspace 中改动处高亮；用户消息只出现一次 |
| FR-7 | 点击 `Create job from this draft` 成功创建职位后，**自动跳转**到该职位的编辑页；无需再点击 `View the created JD` |
| FR-8 | 支持语音输入：允许麦克风权限后转写并发送；拒绝权限时给出提示 |
| FR-9 | AI 失败时显示错误卡片，保留用户输入，提供 Retry 和 Start over；New conversation 清空消息和错误状态 |
| FR-10 | 用户未提供经验年限时，系统查询地区、职能和层级相近的市场岗位，展示多个带岗位、地区、来源和查询日期的年限建议；建议在草稿中高亮且标记“待确认”，用户选定前不写入对外任职硬门槛。无足够可比来源时仅使用定性能力描述，不生成数字建议 |
| FR-11 | 草稿按第 4 节的元数据、对外 a 类五个模块、内部 b/c 类资产呈现；没有输入依据的可选内容保留为空或待确认，不用示例文案填充 |

## 4. 业务规则

| ID | 规则 |
|---|---|
| BR-1 | 点击 Create 之前，系统中不存在新职位；刷新、关闭面板也不产生半成品 |
| BR-2 | 创建后 Core Job `status=draft`，Owner = 当前用户，生成 internal 文档。当前用户归属的线上表现仍需已登录 API 核查；尚未实现的归属能力记为 known gap，不把 UI 现象直接判定为服务端 Owner 错误 |
| BR-3 | 结构化元数据包括：Job Title、Location、Employment Type（创建前均须有值并经用户确认），Job ID（创建时由系统生成）；Salary Range、Department 可选。薪资只有用户明确提供并选择公开时才进入 a 类；内部预算只进入 c 类。未提供的地点、工作性质、学历、福利、预算、编制状态或 Level 不得作为已确认事实自动填写 |
| BR-4 | 草稿及对外 JD 不得把用户未提供、未确认的数字或公司事实写成确定要求或承诺；尤其不得盲目生成具体经验年限、量化业务指标、学历底线、业务规模和福利。市场经验年限只作为 FR-10 的带来源待确认建议，不得自动转成硬门槛 |
| BR-5 | 对外 a 类正文提供五个标准模块：①职位诱惑／公司与团队介绍（有依据时不超过 4 行）；②岗位职责（按重要程度排序，4–6 条，以“负责／主导／设计／推动／优化”等强动词开头）；③任职要求（保留用户给出的硬技能，学历和年限没有依据时留空或用定性能力描述）；④加分项（以“优先”或“具备以下者加分”引导，仅列有依据或待确认的建议）；⑤福利待遇／团队亮点（有已确认信息时以无序列表呈现）。草稿保留五模块结构，缺少依据的模块内容可为空；单独的“概述”不作为必填或本次验收项 |
| BR-6 | 内部 b 类为岗位相关的胜任力维度、结构化行为面试题及判分标准，仅授权面试官、HR、雇佣经理查看；内部 c 类为已确认的招聘背景、预算、编制状态及真实审批记录，仅授权 HR、雇佣经理查看。未经确认的替换原因、预算或审批结果不得推断成事实；年龄、性别等与岗位能力无关的排他性偏好不进入公开或内部筛选标准。a/b/c 可见范围由服务端权限控制 |
| BR-7 | 创建过程不产生审批决定、发布或外发记录；c 类审批流转日志只记录真实发生的事件，不由 AI 编造 |
| BR-8 | Retry 必须幂等，不能重复创建职位 |
| BR-9 | AI 建议的职位名及市场经验年限在用户确认前保持待确认状态；职位名未确认时不可 Create，年限未确认时不进入任职硬门槛 |

## 5. 数据

| 方向 | 对象 | 关键字段 |
|---|---|---|
| 输入 | 用户回答 | 三个问题的文本（中/英），可来自语音转写 |
| 输出 | CopilotConversation / CopilotMessage | 会话 ID、消息、追问记录 |
| 输出 | 草稿元数据 | title、location、employmentType、可选 publicCompensation / department；创建后关联 jobId |
| 输出 | a 类公开正文 | whyJoinUs、responsibilities、mustHave、niceToHave、benefits；可选内容无依据时为空 |
| 输出 | b 类内部面试资产 | 胜任力维度、行为面试题、判分标准及可见范围 |
| 输出 | c 类内部管理资产 | 已确认的招聘背景、真实预算、编制状态、真实审批事件及可见范围 |
| 输出 | 字段溯源与建议 | 每个字段的 source、revision、confirmationStatus；职位名建议、市场年限建议及其岗位、地区、来源和查询日期 |
| 输出 | Core Job | job_id、title、status=draft、createdBy |
| 输出 | JobDocument | a/b/c 分类的块列表，每块有服务端可校验的可见范围 |
| 输出 | AiRun | 模型、prompt 版本、耗时、结果状态 |

## 6. 权限

| 角色 | 能否使用 |
|---|---|
| Recruiter / TA、Hiring Manager | 可以创建 |
| HR Approver | 以角色定义为准（待确认是否可创建） |
| Viewer | 不能创建：入口不可见或不可用（待确认） |

对外 a 类可由获授权的查看者读取；b 类目标读者为面试官、HR、雇佣经理；c 类目标读者为 HR、雇佣经理。具体产品角色与“面试官／HR”的映射及服务端读权限需与 M7 角色模型对齐。AI 上下文只包含本次会话获授权的内容，不读取其他职位的 Confidential 内容。

## 7. 非功能要求

- 性能：首个反馈和完整结果的阈值待确认（测试脚本 v0.1 E11 建议 ≤2 秒 / ≤20 秒）。
- 中英文界面都要支持。
- 同一输入重复生成，结果都要满足 BR-4、BR-5 的判定条件；市场年限建议还须满足 FR-10 的来源和待确认要求。

## 8. 验收标准

| ID | 验收 | 对应闭环路径 |
|---|---|---|
| AC-1 | 三问任意一项缺少有效回答时，只追问缺失项且不生成完整 JD；单字输入不直接生成 | Loop_IO P2、P8 |
| AC-2 | AI 建议的职位名高亮并标记待确认；用户可确认或修改，未确认前不能 Create；无合理建议时追问 title | P3 |
| AC-3 | 生成 1 份符合 BR-4、BR-5 的结构化草稿，逐字段可见来源和确认状态；无依据内容不写成事实，市场年限建议有可比来源且确认前不成为硬门槛；a/b/c 内容按授权范围可见 | P1 |
| AC-4 | 对话修改后改动高亮，用户消息不重复 | P4 |
| AC-5 | Create 前无职位；Create 成功后自动跳转编辑页，符合 BR-2、BR-3，刷新后仍在；尚未实现的归属能力按 known gap 报告 | P1 |
| AC-6 | AI 失败可恢复，Retry 不重复创建 | P5 |

## 9. 依赖与实现

- 后端：`POST copilot/conversations`、`POST copilot/conversations/:id/messages`（流式）、`POST copilot/conversations/:id/confirm-draft`。
- 语音：`POST audio/realtime-ticket`（Doubao 实时转写）。
- 市场年限建议依赖可追溯的相似岗位数据源与检索能力；数据不足时按 FR-10 回退到定性描述。
- 上述字段名与 a/b/c 分类是目标数据契约；当前 Copilot schema 和权限实现尚未覆盖全部字段，不能把 PRD 更新视为功能已上线。
- 已知线上问题：F-001 / #32（AI 请求返回 Sign-in service is unavailable）、F-002 / #33（New conversation 不重置）、F-003（没有 Retry）。

## 10. 待确认

1. “已回答”的判定标准（关键词、LLM 判定还是规则）。
2. 字段来源和待确认状态已确定需要展示；是否展示置信度仍待确认。
3. HR Approver、Viewer 能否使用创建入口；M7 四角色与本模块“面试官／HR”读权限的映射。
4. 性能阈值。
5. 市场相似岗位的数据源、可比性判定与建议数量；数据不足时已确定不输出数字建议。
6. Create a Job 首页未选入口直接输入的分流行为不在当前 M1 验收范围，另行决定。Create 成功后自动跳转编辑页已确认。
