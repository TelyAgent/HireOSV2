## 1. 背景与目标

用户已经知道要招什么职位，希望快速看到几种不同写法并选出最合适的一种。

**目标**：输入职位名后得到三个风格不同、事实一致的版本，选定一个直接创建职位。

## 2. 范围

| 包含 | 不包含 |
|---|---|
| 根据职位名生成 A / B / C 三个风格版本 | 三问引导（M1） |
| 卡片与 Workspace 页签联动对比 | 完整性检查（M6） |
| Refine：一次指令同时修改三个版本 | 审批与发布（M7、M8） |
| 用选中版本创建职位 | |
| 职位名输入校验、含义澄清与误操作恢复 | |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-1 | 点击入口后，入口标题作为用户消息出现；Agent 只发引导文案，不内嵌输入框或按钮；底部输入框聚焦 |
| FR-2 | 用户发送职位名后，职位名在对话中只出现一次，显示生成中状态 |
| FR-3 | 生成三个版本：A Concise & direct、B Warm & people-first、C Detailed & structured |
| FR-4 | 对话中显示 3 张选择卡片；Workspace 顶部有 A / B / C 页签，与卡片选择联动 |
| FR-5 | Refine 指令同时更新三个版本，并高亮改动；停留在当前所选版本 |
| FR-6 | 点击 `Create job with version X` 用所选版本创建职位 |
| FR-7 | 职位名为空时不生成，并提示输入 |
| FR-8 | 发送前去除首尾空格；空白、纯数字或纯符号输入不调用 AI，保留输入并在输入框附近说明应填写职位名称。校验不能仅凭字数拒绝 `CFO`、`UI设计师`、`3D 设计师` 等可识别的名称 |
| FR-9 | 对不完整或缩写有歧义的名称（如 `UI`、`产品`、`运营`），先询问具体职位，提供可选示例和自由输入；用户确认名称前不生成三版。对形式完整但含义少见的名称（如 `Chief Tidy Officer`），可展示三版初稿，但必须在草稿中标明“职位含义待确认”并追问具体职责；确认前不得把猜测的职责或公司事实写成确定内容，也不得创建职位。示例只帮助澄清，不得自动替用户选定 |
| FR-10 | 对疑似拼写错误的名称（如 `Finace Manager`），提出候选修正，让用户确认或保留原文；不得静默改名 |
| FR-11 | 一次输入多个职位时，请用户先选一个；输入明显是整段职责/JD 而非职位名时，提示改用 Paste a Link or Text，并保留原输入供转移；不得截断或悄悄切换入口 |
| FR-12 | 职位名附带地点、工作方式等条件时，先展示解析出的职位名和条件供用户确认；确认后各版本使用同一组条件。无法可靠拆分时追问，不把猜测当作已确认事实 |
| FR-13 | 生成与创建请求进行中，阻止重复提交；AI 或网络失败时保留原始输入、已确认的职位名与条件及当前版本，说明失败原因并提供 Retry / Start over。重试不能重复创建职位 |

### 3.1 职位名输入边界与反馈

| 用户输入 | 处理 | 示例反馈 |
|---|---|---|
| 空串、只有空格 | 阻止发送；不创建会话生成记录或职位 | 请输入职位名称，例如 Finance Manager |
| 纯数字、纯符号 | 阻止生成；保留输入以便修改 | 请输入职位名称，例如 Finance Manager |
| 简短但含义明确 | 正常生成；不设置单纯的最少字数门槛 | `CFO`、`UI设计师`、`3D 设计师` |
| 不完整、缩写有歧义 | 先澄清并允许自由输入；不自动选建议项 | “UI”指 UI 设计师、UI 工程师，还是其他职位？ |
| 形式完整但含义少见 | 三版初稿标明职位含义待确认，在草稿中追问具体职责；确认后更新三版，确认前不可创建职位 | `Chief Tidy Officer` 主要负责什么？请确认后继续 |
| 疑似拼写错误 | 建议修正并允许使用原文 | 是否指 Finance Manager？也可以保留原名称 |
| 多个职位 | 请用户选定本次要创建的一个职位 | 这次先为哪个职位生成 JD？ |
| 整段职责或完整 JD | 建议转到 Paste a Link or Text，保留已输入文字 | 这看起来是职位描述，可用“粘贴链接或文本”创建 |
| 职位名附带条件 | 展示提取结果；确认后生成；无法拆分时追问 | 职位：Finance Manager；地点：上海；工作方式：远程。是否正确？ |

追问和校验都留在当前对话中。用户能修改原文、选择建议或输入自己的名称；不能因为一次误输入就丢失内容或产生半成品职位。

## 4. 业务规则

| ID | 规则 |
|---|---|
| BR-1 | 三个版本的事实字段（职位名、地点、HC、工作方式、薪资）必须一致，只有表达风格不同 |
| BR-2 | 只有本入口生成三个版本；其他入口只生成 1 份草稿 |
| BR-3 | 创建后的职责、要求与所选版本逐字一致 |
| BR-4 | 不得出现输入中没有的公司事实 |
| BR-5 | 创建规则同 M1 BR-1～BR-3、BR-6、BR-7 |
| BR-6 | 不完整或缩写有歧义的职位名，以及尚未确认的附加条件，须先澄清再调用 title-variants。形式完整但含义少见的职位名可生成标记“待确认”的三版初稿，并在草稿中追问职责；确认后更新三版。无需澄清的完整职位名可直接生成 |
| BR-7 | 对话中的建议、纠错和解析结果均不是用户确认。不完整或缩写有歧义的名称澄清前不得生成三版；形式完整但含义少见的名称在含义确认前不得创建 Core Job，也不得把猜测的职责、地点、工作方式、部门等写成确定事实 |
| BR-8 | 本次确认的职位名和事实字段成为三版共享输入；三版只在表达风格上不同。用户明确提供的条件优先于已批准的默认值；未提供字段按公共规则处理，不另造默认值 |
| BR-9 | 每个创建动作只产生一条 Draft。重复点击、超时后重试或结果未知时先查询已有结果，不能凭再次点击创建第二条职位 |

## 5. 数据

| 方向 | 对象 | 关键字段 |
|---|---|---|
| 输入 | 原始文本、确认后的职位名 | 保留原文；职位名经首尾空格清理后非空且含可识别的岗位含义 |
| 输入 | 用户确认的附加条件 | 地点、工作方式等；记录用户提供/默认/待确认的来源 |
| 输入 | Refine 指令 | 文本 |
| 中间状态 | 校验与澄清 | 无效、待澄清、待确认、可生成；保留原输入和建议项 |
| 输出 | 三个版本 | 每个版本的 summary、responsibilities、requirements 等；风格标签 |
| 输出 | 选择结果 | 所选版本标识 |
| 输出 | Core Job + internal 文档 | 内容 = 所选版本 |

## 6. 权限

同 M1：Recruiter / TA、Hiring Manager 可创建；HR Approver、Viewer 待确认。

## 7. 非功能要求

- 三个版本的生成时间阈值待确认。
- 同一职位名生成多次，每次都满足 BR-1。
- 空白、纯数字、纯符号等确定性校验不触发 LLM 生成或 AiRun。不完整或缩写有歧义的名称在澄清阶段不调用 title-variants；形式完整但含义少见的名称可生成标记待确认的初稿，但确认前不创建职位。服务端同样验证关键输入，不能只依赖前端按钮状态。
- 故障后可恢复原输入和已确认条件；重复提交、Retry 与 Create 均遵守 BR-9。

## 8. 验收标准

| ID | 验收 | 对应闭环路径 |
|---|---|---|
| AC-1 | 生成三个风格版本，事实字段一致 | P1 |
| AC-2 | Refine 后三版一起更新，停留在当前版本 | P2 |
| AC-3 | 创建内容与所选版本一致 | P1 |
| AC-4 | 空白、纯数字和纯符号输入不触发生成，显示可理解的校验反馈；短而明确的职位名仍可生成 | P3、输入边界 |
| AC-5 | AI 失败可恢复 | P4 |
| AC-6 | 不完整或缩写有歧义的职位名先得到澄清，确认前没有三版草稿或职位；形式完整但含义少见的名称可出现标记待确认的三版初稿，草稿中追问具体职责且不写入猜测事实，确认前不能创建职位，确认后更新三版 | 输入边界 |
| AC-7 | 疑似拼写错误可选择修正或保留原文；多职位输入先选定一个；整段 JD 可带原文转入 Paste a Link or Text | 输入边界 |
| AC-8 | 附带条件先经用户确认；三版及所选版本创建后的事实字段与确认结果一致，不静默补入公司事实 | 输入边界、P1 |
| AC-9 | 连续点击 Send/Create 和失败后 Retry 不能重复生成职位；失败后输入、确认条件和所选版本可恢复 | 输入边界、P4、P6 |

## 9. 依赖与实现

- 后端：`POST copilot/conversations/:id/title-variants`、`POST copilot/conversations/:id/refine-variants`、`POST copilot/conversations/:id/confirm-draft`。

## 10. 待确认

1. “事实一致”用字段级比对还是 LLM 判定。
2. 哪些字段允许 AI 填默认值，界面是否标注“默认”。
3. 对 `Chief Tidy Officer` 一类形式完整但含义少见的名称，已确定在三版初稿中标明待确认并追问具体职责，确认前不能创建职位；如何识别“含义少见”的具体边界待评审。
4. “整段职责/JD”的识别提示和超长输入上限的具体阈值。
