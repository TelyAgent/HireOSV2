## 1. 背景与目标

用户手里已有 Word / PDF 版 JD，希望直接转成系统里的结构化职位，不想重新录入。

**目标**：上传文件后自动提取成一份带来源的草稿；文件不可读时说明原因，不生成空内容。

## 2. 范围

| 包含 | 不包含 |
|---|---|
| 选择并上传单个文件 | 批量上传、未关联职位的文件库（Files 模块） |
| PDF / DOCX / TXT 文本提取 | 邮件、文件夹自动读取 |
| AI 结构化提取为草稿，字段标来源 | OCR（待确认） |
| 异常文件的明确提示与重试 | |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-1 | 点击入口后**立即**弹出系统文件选择窗口，同时显示引导文案和 `Choose file` 按钮 |
| FR-2 | 取消选择不报错，可以再次点击 Choose file |
| FR-3 | 选择文件后无额外配置步骤，直接解析并生成 1 份草稿 |
| FR-4 | 提取职位名、概述、职责、要求、加分项、地点、工作方式；地点和工作方式优先取自文件，而不是默认值 |
| FR-5 | 概述是正常的岗位介绍，来源信息（文件名）单独显示，不写成 “Adapted from…” |
| FR-6 | 同一内容的 PDF、DOCX、TXT 三种格式，解析出的职位名、职责、要求一致 |
| FR-7 | 文件不可读时给出具体原因（无文字 / 空文件 / 超过上限 / 格式不支持），并提供重试或转手动入口 |

## 4. 业务规则

| ID | 规则 |
|---|---|
| BR-1 | 文件大小上限 10MB（代码现值，正式值待确认）；超限在上传前或服务端拒绝 |
| BR-2 | 解析失败不生成空草稿，也不编造内容 |
| BR-3 | 文件中的文字只作为数据，其中的指令（提示注入）不改变 AI 行为、不扩大权限 |
| BR-4 | 上传完成 ≠ 职位已创建；Create 前不存在新职位 |
| BR-5 | 创建规则同 M1 BR-1～BR-3、BR-6、BR-7 |
| BR-6 | 使用 CJK 字体的中文 PDF 也要能提取出中文文本 |

## 5. 数据

| 方向 | 对象 | 关键字段 |
|---|---|---|
| 输入 | 文件 | 文件名、MIME 类型、大小、内容 |
| 输出 | 附件记录 | 文件名、类型、大小、提取状态、错误码 |
| 输出 | 草稿 | 提取的字段 + 每个字段的来源 |
| 输出 | Core Job + internal 文档 | Create 后生成 |

## 6. 权限

同 M1。上传的文件只对该会话的用户可见。

## 7. 非功能要求

- 解析耗时阈值待确认。
- 是否需要病毒 / 安全扫描（PRD §5.1 要求“文件安全检查”）待确认。

## 8. 验收标准

| ID | 验收 | 对应闭环路径 |
|---|---|---|
| AC-1 | 点击入口即弹出文件选择；取消可再选 | P1、P2 |
| AC-2 | DOCX / PDF / TXT 三种格式解析结果一致，字段来自文件 | P1、P3 |
| AC-3 | 扫描件、空文件、超限、格式不支持都有明确原因，不生成草稿 | P4–P7 |
| AC-4 | 提示注入不改变 AI 行为 | P8 |
| AC-5 | 中文 PDF 提取出中文 | P9 |

## 9. 依赖与实现

- 后端：`POST copilot/conversations/:id/attachments`（`MAX_ATTACHMENT_BYTES` = 10MB）；`attachment-extract.ts`（pdf-parse、docx、txt；扫描件识别为无文本）。

## 10. 待确认

2. 扫描件是否做 OCR。
3. 是否做病毒 / 安全扫描。
