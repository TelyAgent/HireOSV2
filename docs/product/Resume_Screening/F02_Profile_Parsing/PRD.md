## 1. 背景与目标

简历是候选人的证据来源，不是候选人本身。后续的匹配、筛选和对比都依赖结构化资料，而且每个结论都要能追溯到简历原文。

**目标**：把简历转成有版本的结构化档案；原文始终保留；人工纠正产生新版本；AI 不编造简历中没有写的信息。

## 2. 范围

| 包含 | 不包含 |
|---|---|
| 从简历文本提取结构化资料 | 文件接收与安全检查（F01） |
| 档案版本、简历版本 | 身份合并（F03） |
| 人工纠正解析结果 | 岗位匹配（F06） |
| 候选人详情页：资料、履历时间线、材料版本、岗位关系 | 筛选评估（F08） |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-1 | 按 4.1 的字段清单解析简历；每个字段记录值、状态和来源位置（材料版本、页码、段落） |
| FR-2 | 简历没有写的字段显示「未提供」，不用空值或默认值冒充 |
| FR-3 | 用户可以纠正解析结果；保存后生成新的档案版本，原文和旧版本保留；纠正原因规则见 4.3 |
| FR-4 | 同一候选人可以有多份简历版本，详情页列出全部版本、来源和上传时间 |
| FR-5 | 详情页展示履历时间线，以及该候选人与所有岗位的关系（推荐中 / 已关联 / 已拒绝提案） |
| FR-6 | 解析失败时明确显示失败原因，并允许重试解析或手动录入 |
| FR-7 | 内部技术 ID 和 hash 收在详情 / 审计区，不出现在主流程 |

## 4. 业务规则

| ID | 规则 |
|---|---|
| BR-1 | 禁止 AI 补造简历中未写明的薪资、签证、离职原因或公司规模 |
| BR-2 | 原文和结构化字段同时保存；纠正只产生新版本，不改写原文 |
| BR-3 | 简历中的指令视为内容，不改变解析规则 |
| BR-4 | 新简历版本不覆盖已有评估依据；如果影响当前推荐或筛选结果，把相关结果标为「待更新」 |
| BR-5 | 薪资保留原始币种、周期和税前 / 税后，不在解析阶段换算 |
| BR-6 | 不从姓名、照片推断性别、年龄、国籍等受保护属性 |

### 4.1 解析字段清单与格式

| 字段 | 格式 | 说明 |
|---|---|---|
| 姓名 `displayName` | 文本，≤ 200 字符 | 必填；简历未写时用文件名兜底，并标为待确认 |
| 邮箱 `email` / 电话 `phone` | 邮箱转小写；电话可识别时转为 E.164，否则保留原文 | 受限字段 |
| 所在地 `location` | 国家 + 城市 + 原文 | 与 F05 岗位标准的「国家 + 城市」对齐 |
| 工作授权 `workAuthorization` | 原文 | 规则见 4.2 |
| 工作经历 `employmentHistory` | 公司、职位、开始、结束、成就（每段 ≤ 10 条）；日期统一为 `YYYY-MM`，在职写 `present`，无法识别的保留原文并标为部分识别 | 最多 15 段，最近的在前 |
| 总工作年限 | 由工作经历计算，不由 AI 估算 | 标为推导值；重叠时间段不重复计算 |
| 教育 `education` | 学校、学历、专业、起止时间 | 拆分字段，供 F05 学历要求比较 |
| 技能 `skills` | 保留简历原文，不翻译，≤ 40 项 | |
| 语言 `languages` | 语言 + 水平（简历写明才记录），≤ 15 项 | 对应 PRD §5.7 听说读写与验证方式 |
| 证书 `certifications` | 名称，≤ 15 项 | |
| 项目 `projects` | 名称 + 描述，≤ 10 项 | |
| 薪资期望 `compensationExpectation` | 最小值、最大值、币种（ISO 4217）、周期（年 / 月 / 时）、税前 / 税后 / 未知 | 受限字段；未写为空 |
| 到岗时间 `availability` | 原文；可识别时转为日期或天数 | 供 F10 对比「条件与可行性」使用 |

| ID | 规则 |
|---|---|
| FLD-1 | 每个字段都有值、状态（已知 / 未提供 / 部分识别）和证据位置（材料版本、页码、段落） |
| FLD-2 | 性别、年龄、出生日期、照片、婚姻状况、国籍、宗教即使简历中写明也不提取 |

### 4.2 工作授权

| ID | 规则 |
|---|---|
| WA-1 | 保留字段，仅作为候选人自述信息记录；只有简历明确写明时才记录，未写为空，AI 不推断 |
| WA-2 | 不计入缺失字段，不提示「资料不全」 |
| WA-3 | 不参与岗位匹配、评分和对比，不生成待核实项 |
| WA-4 | 标为受限字段，只有有权限的角色可见（公民身份、签证类型可能成为国籍的代理指标） |

### 4.3 纠正原因

| ID | 规则 |
|---|---|
| COR-1 | 被纠正的字段已被有效的推荐或评估使用时，原因必填；其他情况选填 |
| COR-2 | 原因可快选：解析错误 / 候选人补充或更正 / 来源资料更新 / 其他；选「其他」时必须填写文字说明 |
| COR-3 | 每次纠正记录原值、新值、纠正人、时间、原因 |

## 5. 数据

| 方向 | 对象 | 关键字段 |
|---|---|---|
| 输入 | Material | 提取文本、分段 |
| 输出 | Candidate | candidate_id、显示名、负责人 |
| 输出 | CandidateProfile | 版本号、4.1 的结构化字段（含状态与证据位置）、解析器版本、缺失字段、纠正记录（原值、新值、纠正人、时间、原因） |
| 输出 | ResumeVersion | 版本号、material 引用、来源、上传时间 |
| 输出 | ProcessingJob | 解析任务状态、错误、重试 |

## 6. 权限

- 联系方式、薪资期望、工作授权等敏感字段只对有权限的角色显示，其他角色只看到「受限」标记。
- 纠正档案需要候选人的编辑权限，并写入审计。

## 7. 非功能要求

- 中文简历（含 CJK 字体 PDF）能正确提取。
- 解析耗时阈值待确认。

## 8. 验收标准

| ID | 验收 | 对应 |
|---|---|---|
| AC-1 | 解析后的每个字段都能定位到原文位置；原文不可用时显示 unavailable | SCR-03、PRD §8.2 |
| AC-2 | 简历没写的薪资、签证等字段显示「未提供」，没有被 AI 编造 | PRD §4、J4-3 |
| AC-3 | 人工纠正后生成新档案版本，旧版本和原文可查 | PRD §4 |
| AC-4 | 上传新版本简历后，已有评估标为待更新，没有被改写 | PRD §4.1 |
| AC-5 | 详情页能看到全部简历版本和全部岗位关系 | PRD §4.2 |
| AC-6 | 无权限角色看不到敏感字段的值 | PRD §13.7 |
| AC-7 | 解析结果包含 4.1 的全部字段；日期为 `YYYY-MM`，总工作年限由经历计算且重叠时间不重复计算 | 4.1 |
| AC-8 | 简历中写明的性别、年龄、出生日期等信息未被提取 | 4.1 FLD-2 |
| AC-9 | 简历未写工作授权时不出现在缺失字段中；写明时只有有权限的角色可见，且不影响匹配和评分 | 4.2 |
| AC-10 | 纠正已被评估使用的字段时必须填写原因；选「其他」时必须有文字说明；纠正记录可查原值和新值 | 4.3 |
