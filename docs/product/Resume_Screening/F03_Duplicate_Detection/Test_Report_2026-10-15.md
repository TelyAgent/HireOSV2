## 4. 缺陷与异常

### F03-LIVE-01 / P0：身份复核缺关键差异和逐信号评分

- **复现**：上传 `f03_same_email_new_version_20261015.txt`，点击批次“复核”。
- **证据**：复核页只列文件、邮箱、电话、来源、时间和一条邮箱命中，给“匹配置信度 90%”；没有姓名/电话/工作/教育/内容信号的分值、总分、算法版本及履历差异。
- **影响**：Recruiter 缺少规格要求的判断依据，却能直接作合并决定；可能误合并候选人。
- **修复验收**：复核页并排展示新旧履历差异与全部命中/冲突信号、各自分值、总分、策略版本；验证 ≥70、40～69、<40 三档结果及其无自动合并行为。

### F03-LIVE-02 / P1：两种身份处理点击后立即生效

- **复现**：在两条合成复核中分别点击“同一人 — 合并为新版本”和“不同人 — 保持分开”。
- **证据**：两次均直接进入“已处理”状态，没有对象、差异及影响范围的二次确认。
- **影响**：误点即可改变候选人身份处理结果；与 PRD FR-6、User Journey 步骤 7 和 UX U5 不符。
- **修复验收**：提交前展示新旧对象、文件/版本和影响，明确确认/取消；取消不写入，确认后仅写入一次。

### F03-LIVE-03 / P1：结果页处理人为空

- **证据**：两个已处理复核页均显示“处理人： · 2026年10月15日…”，刷新同一人复核链接后仍为空。
- **影响**：页面无法追溯是谁做了身份判断；服务器审计字段是否为空尚未验证。
- **修复验收**：复核结果和审计中显示真实操作身份、时间及结果；刷新后保持一致。

### F03-LIVE-04 / P1：同邮箱同电话被描述成“联系方式不同”

- **证据**：本次上传和已有档案的邮箱相同，上传结果及复核页却写“Name matches an existing candidate, contact details differ”；详情中可见相同邮箱和电话，检测依据也写邮箱一致。
- **影响**：提示与证据相矛盾，干扰人工身份判断。
- **修复验收**：按真实命中与冲突信号生成文案；同邮箱同电话场景不得提示联系方式不同。

### F03-LIVE-05 / P2：完全相同文件结果未指向已有候选人

- **证据**：改名上传后显示“已存在 — 已复用”“无需操作”，批次没有已有候选人名称或打开档案入口。
- **影响**：Recruiter 无法从重复提示直接确认命中对象或继续查阅。
- **修复验收**：有权查看时显示匹配候选人及打开入口；无权查看时遵循 AC-7/10 的零泄露规则。

### F03-ENV-01 / 环境异常：一次上传被认证服务拒绝

- **证据**：首次上传改名文件时显示“上传请求被拒绝，这些文件都没有导入。(Sign-in service is unavailable.)”；关闭面板后重试同一文件成功并被复用。
- **影响**：一次短暂失败，不能据此断言 F03 去重失败；错误缺少清晰中文恢复步骤。建议结合当时认证服务日志核对原因与频率。
