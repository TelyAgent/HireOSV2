## 1. 背景与目标

同一份简历经常从多个渠道重复到达，同一个人也会投递更新后的简历；同时，同名不同人的情况也不少见。自动合并错了会污染候选人历史，不合并又会产生重复的候选人和任务。

**目标**：完全相同的文件不重复建人；疑似同一人一律交给人工判断，不自动合并；判断错了可以纠正。

## 2. 范围

| 包含 | 不包含 |
|---|---|
| 四层重复检测，覆盖同批次和已有简历库 | 跨租户识别 |
| 重复复核任务和复核页 | 多岗位关联（不属于重复，见 F07） |
| 人工处理：同一人 / 不同人 / 补资料 / 暂缓 | |
| 错误合并的拆分纠正 | |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-1 | **完全相同文件**：按文件内容摘要识别（与文件名无关），提示「该文件已存在」并指向已有候选人；复用文件内容，保留本次来源记录 |
| FR-2 | **内容相同、格式不同**：按 4.1 规范化解析文本后比较，标为疑似内容重复并展示依据 |
| FR-3 | **同人不同版本**：按 4.2 的多信号打分识别，提示可能是更新后的简历；人工确认后作为该候选人的新简历版本，旧版保留 |
| FR-4 | **身份相似但不确定**：按 4.2 打分落在复核区间时，生成重复复核任务 |
| FR-5 | 复核页并排展示新旧记录的来源、上传时间、版本和差异，以及命中的信号和各自得分 |
| FR-6 | 复核可选：同一个人（存为新版本）、不是同一个人、需要补资料、暂缓；关键选择需要二次确认 |
| FR-7 | 解析失败、无法做文本比较时，显示「未完成重复检查」，不显示「无重复」 |
| FR-8 | 错误合并可以拆分纠正，并提示受影响的岗位关联需要复核 |

## 4. 业务规则

| ID | 规则 |
|---|---|
| BR-1 | 疑似重复绝不自动合并，不按姓名自动合并；只有姓名一致或相近不足以触发复核（见 4.2） |
| BR-2 | 完全相同文件的自动去重只复用存储内容，不代表身份已确认，也不代表岗位已关联 |
| BR-3 | 完全相同文件不重复创建 Candidate、Application 或分析任务 |
| BR-4 | 并发上传同一文件时原子去重，只保留一条 |
| BR-5 | 只在同一租户内识别；重复提示只展示当前用户有权查看的记录，不能通过提示泄露其他租户或受限候选人 |
| BR-6 | 同一个人关联多个岗位不算重复 |
| BR-7 | 所有处理和纠正写入审计；拆分不破坏历史证据 |
| BR-8 | 文件重复和身份重复分开记录、分开统计 |

### 4.1 内容相同、格式不同

| ID | 规则 |
|---|---|
| CNT-1 | 比较前规范化：全角转半角、统一小写；去掉所有空白、换行、标点和项目符号；去掉页眉、页脚和页码 |
| CNT-2 | 规范化后少于 200 个字符的文本不做相似比较 |
| CNT-3 | 相似度按 5 字符切片的重合率计算 |
| CNT-4 | 完全一致或相似度 ≥ 0.95：判定为「内容相同、格式不同」；0.80～0.95：不单独判定，作为 4.2 的一个信号；< 0.80：不算内容重复 |
| CNT-5 | 阈值保存在策略版本中，试点后校准 |

### 4.2 同人判断信号与权重

| 信号 | 分值 |
|---|---|
| 邮箱一致（不区分大小写） | +40 |
| 电话一致（只比较数字，至少 7 位） | +30 |
| 工作经历重合（≥ 2 段的公司、职位、开始年月都相同） | +20 |
| 姓名规范化后一致 | +15 |
| 姓名相近（只差 1 个字符） | +8 |
| 内容相似度 0.80～0.95 | +15 |
| 教育经历一致（学校、专业、时间） | +10 |
| 冲突：两边都有邮箱和电话，且都不相同 | −30 |

| ID | 规则 |
|---|---|
| ID-1 | 满分 100；总分 ≥ 70 提示「可能是同一人的新版本」，40～69 生成重复复核任务，< 40 不提示 |
| ID-2 | 所有信号合并打分，不因单个信号命中直接定结论，也不在找到第一条匹配时停止 |
| ID-3 | 任何分数都不自动合并，均需人工确认 |
| ID-4 | 每次判断记录命中的信号、各自得分和算法版本；分值和阈值保存在策略版本中 |

### 4.3 无权查看的可能重复

| ID | 规则 |
|---|---|
| RST-1 | 可能重复的已有记录当前用户无权查看时，对上传者不做任何提示，照常入库 |
| RST-2 | 后台生成重复复核任务，交给对两条记录都有权限的 HR Approver 队列 |
| RST-3 | 复核完成前，新记录照常保留，不合并 |

### 4.4 补资料与暂缓

| | 补资料 | 暂缓 |
|---|---|---|
| 任务状态 | 等待中（waiting），不算完成 | 等待中（waiting），不算完成 |
| 必填 | 需要补充的资料 | 原因 + 复查时间（1 / 3 / 7 天，默认 3 天） |
| 自动恢复 | 任一方出现新简历版本或资料纠正时回到待处理，并提醒负责人 | 到复查时间回到待处理，并提醒负责人 |
| 到期提醒 | 默认 3 个工作日后提醒负责人 | 到复查时间提醒 |
| 升级 | 7 个工作日仍未处理，提醒队列管理者 | 同左 |

| ID | 规则 |
|---|---|
| WAIT-1 | 等待期间重复判断保持未处理，两条记录不合并 |
| WAIT-2 | 新记录可以正常参与岗位推荐；确认岗位关联时提示「存在未处理的重复复核」 |
| WAIT-3 | 「逾期」是派生标记，不是独立状态；临期和逾期提醒合并为摘要发送 |
| WAIT-4 | 负责人可以随时手动恢复任务 |

## 5. 数据

| 方向 | 对象 | 关键字段 |
|---|---|---|
| 输入 | Material、CandidateProfile | 内容摘要、规范化文本、身份信号 |
| 输出 | DuplicateCheck | 检测类型、算法 / 策略版本、相似度、命中信号及得分、总分、候选重复记录、检查状态 |
| 输出 | DuplicateResolution | 处理结果、操作人、时间、备注 |
| 输出 | HumanTask | 重复复核任务（类型 duplicate_review）；等待原因、复查时间、路由队列 |

## 6. 权限

- 处理复核需要对涉及的所有候选人都有编辑权限。
- 无权查看的已有记录不出现在提示中，对上传者不做任何提示，复核交给有权限的队列（见 4.3）。

## 7. 非功能要求

- 检测在入库主流程中完成，不让用户等待人工复核才能看到文件已接收。

## 8. 验收标准

| ID | 验收 | 对应 |
|---|---|---|
| AC-1 | 同一文件改名后重复上传、同批次重复、并发上传：复用内容、保留来源，不重复创建候选人、关联或任务 | SCR-23、J3-5 |
| AC-2 | 不同格式同内容、同人新版本，分别显示不同的提示和依据 | SCR-24、J3-3 |
| AC-3 | 同名不同人不自动合并；只有姓名一致或相近、其他信号不足（总分 < 40）时不提示、不生成复核任务 | SCR-24、J3-4 |
| AC-4 | 复核选「不是同一个人」后两条记录保持分开，任务关闭并留记录 | J3-11～12 |
| AC-5 | 解析失败时显示未完成检查，不显示无重复 | PRD §4.1 |
| AC-6 | 错误合并可拆分，历史证据保留 | PRD §4.1 |
| AC-7 | 提示中不出现其他租户或无权查看的候选人信息 | PRD §4.1 |
| AC-8 | 同一简历的 PDF 和 DOCX 版本判定为内容相同；规范化后少于 200 字符的文本不做比较 | 4.1 |
| AC-9 | 同人判断按多信号合并打分，复核页展示命中信号与得分；≥ 70、40～69、< 40 三档结果正确 | 4.2 |
| AC-10 | 可能重复的记录对上传者无权查看时，上传者看不到任何提示，复核任务出现在有权限的队列中 | 4.3 |
| AC-11 | 补资料、暂缓后任务为等待中，不算完成；到期或出现新资料后自动恢复并提醒；7 个工作日未处理升级给队列管理者 | 4.4 |
