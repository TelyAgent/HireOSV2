## 4. 缺陷与复现步骤

| ID / 建议级别 | 可观察证据与影响 | 最小修复及验收 |
|---|---|---|
| F01-FMT-01 / **P1** | 11 页 PDF `UJ-TEST-F01-11-pages.pdf` 被成功入库，违反单文件最多 10 页的 BR-2/AC-3；超页内容进入候选人及后续匹配 | 服务端在入库前校验页数，前端显示“超过 10 页”；复测 10 页可通过、11 页不建候选人 |
| F01-FMT-02 / **P1** | 已加密 PDF 被报“扫描件无法提取文字”，UI 不显示隔离；用户不知道文件有密码，安全状态不可辨 | 在安全扫描阶段识别 `/Encrypt` 并隔离，展示加密原因；核对 Material.securityStatus、隔离原因与无 AiRun/候选人 |
| F01-FMT-03 / **P2** | 36 字节损坏 PDF 被报扫描件，错误分类不准确 | 区分“文件损坏/无法解析”和“扫描件无文字”，提供重选文件路径 |
| F01-FMT-04 / **P2** | PNG 显示 `Bad Request Exception UNSUPPORTED_FILE_TYPE` 与“无需操作” | 显示支持格式和重新选择动作；复测 `.png`、`.zip` 均不建人 |
| F01-FMT-05 / **P1，跨 F02/F03 待定位** | 首批 PDF 的姓名被识别为 `Location: Hanoi, Vietnam`，再与 `valid.txt` 仅凭低置信度姓名/文件名相似进入复核；正常导入被卡住 | 排除地点标签作为姓名；检查姓名、邮箱和文件名的优先级，复测首批样本并核对重复判断依据 |

本地代码的姓名提取逻辑会排除包含连续四位数字的行；首批姓名行带 `20261015`，可能使地点行成为第一个合格候选。这是**基于本地代码的定位线索**，未取得线上构建号，不能直接当成线上根因结论。
