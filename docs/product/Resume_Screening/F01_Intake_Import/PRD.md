## 1. 背景与目标

简历来自上传、粘贴、CSV 和企业邮箱等多个渠道。HR 希望不管从哪里来，都能用同一套流程进入系统，并清楚看到每个文件的处理结果。

**目标**：所有来源的简历都能保存下来并记录来源；一个坏文件不影响同批次的其他文件；失败的条目可以单独重试。

## 2. 范围

| 包含 | 不包含 |
|---|---|
| 手动上传 PDF / DOCX / TXT（单个或多个） | 简历解析为结构化资料（F02） |
| 粘贴文本资料（Paste profile） | 重复识别规则（F03） |
| CSV 批量导入 | API 接入 |
| 从已连接的邮箱读取简历 | 文件夹导入 / 文件夹监控 |
| 文件安全检查与隔离 | 邮箱连接的授权和配置（Files & Integrations，见功能拆分 F17） |
| 导入批次、逐条状态、失败重试、取消 | Scout 寻人、冷触达 |
| | 绕过第三方平台权限的抓取 |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-1 | 简历库提供 **Upload resumes** 和 **Paste profile** 两个入口，上传时不要求选择岗位 |
| FR-2 | 支持一次选择多个文件；每个文件单独显示处理进度（接收 → 安全检查 → 读取 → 身份识别）和最终结果 |
| FR-3 | 粘贴资料时自动识别姓名、邮箱、所在地并填入表单；所在地只取地点本身，不带后面的整句话；姓名必填 |
| FR-4 | 支持 CSV 批量导入，导入前展示字段映射；映射不全的条目进入 `needs_mapping` |
| FR-5 | 从已连接的邮箱读取到的简历进入同一条处理流程，并记录读取来源 |
| FR-6 | 每条来源记录原始渠道（Manual upload / Paste / CSV / Email / Referral / Job board 等）和 `source_record_id` |
| FR-7 | 文件先做安全检查；加密、带病毒或无法安全处理的文件进入**隔离**，说明原因，不送入 AI、不进入简历库 |
| FR-8 | 扫描件（无可复制文字）、空文件、超过大小上限、不支持的格式，分别给出明确原因，并回到可重试状态 |
| FR-9 | 导入批次显示 received / parsed / needs_mapping / queued / running / completed / failed / cancelled 各状态的数量 |
| FR-10 | 批次中部分失败时，批次结果为 `partial_success`；失败条目可单独重试 |
| FR-11 | 取消批次只停止未完成的条目，已完成的结果保留 |

## 4. 业务规则

| ID | 规则 |
|---|---|
| BR-1 | 保存来源 → 安全检查与重复识别 → 解析 → 入库，顺序固定；上传成功 ≠ 入库成功 ≠ 已匹配岗位 |
| BR-2 | 单文件上限 25MB（代码现值，正式值待确认）；超限在上传前或服务端拒绝 |
| BR-3 | 失败文件不产生半成品候选人 |
| BR-4 | 重试只处理失败条目，不重复处理已成功的条目，不重复建人、不重复建任务；供应商侧的重试费用单独记成本 |
| BR-5 | 材料中的文字只作为数据，其中的指令（提示注入）不改变 AI 行为、权限或评分规则 |
| BR-6 | 读取成功不等于导入成功；邮箱的「已读取」和本模块的「已消费」是两个状态 |
| BR-7 | 按租户限流；只显示队列状态，不编造精确完成时间 |
| BR-8 | 判定按文件内容，不按文件名 |

## 5. 数据

| 方向 | 对象 | 关键字段 |
|---|---|---|
| 输入 | 文件 / 粘贴文本 / CSV 行 / 邮件附件 | 文件名、MIME、大小、内容、来源渠道、`source_record_id` |
| 输出 | Material | 内容摘要（hash）、安全检查状态、读取状态、提取状态、错误码 |
| 输出 | ImportBatch / ImportItem | 批次状态、各状态计数、逐条状态与错误、重试次数 |
| 输出 | IngestionOperation / IngestionAttempt | 每次处理尝试、阶段、结果 |
| 输出 | CandidateSource | 渠道、原始记录 ID、接收时间 |

## 6. 权限

- 有简历库写权限的用户可以上传和粘贴；批次只对发起人和有该简历库权限的人可见。
- 隔离文件的原文只对管理员可见，用于排查。

## 7. 非功能要求

- 100 份简历的批次中，一份失败不阻断其余 99 份。
- 并发上传同一文件时只处理一次（见 F03）。
- 单文件处理耗时阈值待确认。

## 8. 验收标准

| ID | 验收 | 对应 |
|---|---|---|
| AC-1 | 不选岗位即可上传简历，结果进入简历库 | SCR-25、J3-2 |
| AC-2 | 多文件上传时每个文件独立显示结果，一个失败不影响其他 | SCR-06、J3-10 |
| AC-3 | 扫描件、加密文件、不支持的格式、超大文件各有明确原因，不生成候选人 | J3-6～9 |
| AC-4 | 100 份中一份解析失败：其余完成，失败条目可重试，成功项不重复处理 | SCR-06 |
| AC-5 | 粘贴资料能识别姓名、邮箱、所在地，所在地不带多余文字；缺姓名不能保存 | J4-1～3 |
| AC-6 | 取消批次后，已完成的结果保留，未完成的停止 | PRD §7 |
| AC-7 | 文件中的提示注入不改变 AI 行为 | PRD §4 |

- 后端：`src/intake`（`materials.service.ts`、`imports.service.ts`、`security-scan.service.ts`）、`src/profiles`；接口 `POST materials`、`POST imports`、`POST import-items/:id/...`。
- 前端：`LibraryPage`、`features/imports`。
