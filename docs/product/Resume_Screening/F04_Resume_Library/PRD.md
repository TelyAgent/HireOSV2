## 1. 背景与目标

简历经常先于岗位到达，或者暂时没有合适的岗位。如果必须先选岗位才能保存简历，这些候选人就会丢失。

**目标**：简历库独立于岗位存在；候选人不论有没有关联岗位都保留在库里，随时可以被新岗位重新发现。

## 2. 范围

| 包含 | 不包含 |
|---|---|
| 候选人列表、搜索、筛选 | 导入流程本身（F01） |
| 标签、负责人、来源、匹配状态 | AI 匹配逻辑（F06） |
| 无推荐时的后续处理入口 | 人工关联（F07） |
| 保留状态、可联系状态 | 保留策略配置（权限与审计，功能拆分 F19） |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-1 | 页面说明「候选人无论是否关联岗位都保留在这里，简历可以早于岗位到达」 |
| FR-2 | 列表列：候选人、标签、最近来源、负责人、匹配状态、最近匹配时间、关联岗位数；显示「N of M candidates」 |
| FR-3 | 支持按姓名、标签、来源、负责人、匹配状态、入库时间搜索和筛选 |
| FR-4 | 可以编辑标签和负责人 |
| FR-5 | 匹配状态按 F06 的状态显示（未开始 / 匹配中 / 有推荐 / 暂无合适岗位 / 没有开放岗位 / 资料不足 / 失败），并说明原因 |
| FR-6 | 没有推荐时，提供：人工搜索岗位、补资料、设置复查时间、重新匹配 |
| FR-7 | 点击候选人进入详情（F02）；从详情进入「适合的岗位」（F06 / F07） |
| FR-8 | 空库时显示空状态和上传入口 |

## 4. 业务规则

| ID | 规则 |
|---|---|
| BR-1 | 一个候选人可以关联 0 个、1 个或多个岗位；关联后仍然属于简历库，不使用「在库 / 已关联」互斥状态 |
| BR-2 | 没有岗位时不创建虚拟岗位或虚拟 Application |
| BR-3 | 「暂无合适岗位」只代表当前岗位集合和资料版本下没有匹配，不代表候选人不合格 |
| BR-4 | 没有可处理的问题时，不反复生成无意义的待办 |
| BR-5 | 已删除或受保留策略限制的资料不再参与自动匹配 |
| BR-6 | 来源只用于运营筛选，不参与评分 |

## 5. 数据

| 方向 | 对象 | 关键字段 |
|---|---|---|
| 输出 | LibraryEntry | entry_id、workspace、candidate / profile / resume 引用（或待身份确认的来源）、负责人、标签、来源、保留状态、入库时间、最近匹配时间；job / application 可以为空 |

## 6. 权限

- 列表只显示当前用户有权查看的候选人。
- 删除候选人需要专门权限，并写入审计；删除后不再自动匹配。

## 7. 非功能要求

- 大量候选人时列表分页或虚拟滚动，筛选条件和滚动位置在返回时保留。

## 8. 验收标准

| ID | 验收 | 对应 |
|---|---|---|
| AC-1 | 只上传简历、没有任何岗位，候选人进入简历库 | SCR-25、J3-1 |
| AC-2 | 无岗位、无匹配、资料不足、AI 失败四种状态分开显示 | SCR-25 |
| AC-3 | 已关联岗位的候选人仍出现在简历库中 | PRD §4.2 |
| AC-4 | 无推荐的候选人可以人工搜索岗位或设置复查 | PRD §4.2 |
| AC-5 | 列表只显示有权限的候选人 | PRD §4.1 |
| AC-6 | 刷新后数据保持（持久化） | J3-13 |
