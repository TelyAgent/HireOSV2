# F10 候选人对比：线上测试与 UX/UI 审查报告

测试时间：2026-10-15 约 10:17–10:25 CST。**结论：不通过完整验收。**按 16 条用例统计：通过 0、部分验证 7、失败 3、未验证 6。线上对比页可创建双人快照、呈现条件性差异、隐藏相同维度并保留刷新前快照；但逐人下一步入口缺失，v2 的历轮变化被误写为“第一个快照”，中文界面仍有英文内容。权限、通知、审计、导出文件和异常路径缺乏线上证据，不能推定通过。

## 2. 线上操作与证据

| 证据 | 操作及可见结果 | 证明范围 |
|---|---|---|
| E-01 | 岗位工作台加载完成后显示“已关联候选人 2”，候选人对比按钮可用；点击后进入上述对比 URL，生成 v1 | 两名已关联候选人的页面主入口可用；未证明“三人勾选”、成员 DB 或审计 |
| E-02 | v1 顶部有岗位、添加候选人、刷新、导出、三模式和快照选择器；主要差异按条件表达取舍，未给赢家或录用概率；矩阵按候选人列展示分数、证据状态、薪酬及技术测评 | 双人可见比较；差异摘要没有逐条可点击的要求/证据引用 |
| E-03 | 两名样例候选人的技术测评均显示“未评估”；Compensation & Location Fit 均为“未知”；薪酬均显示同一币种和周期的非零范围 | 未评估及未知的这组数据没有被写成能力低或 0；未覆盖一人已测、一人未测或混合币种 |
| E-04 | 切到“同一阶段”，选中态改变；该组矩阵内容与“当前汇总”一致。勾选“仅显示差异项”后，相同的“技术测评”“薪酬与所在地”等行被隐藏 | 差异过滤有效；因两人处在同一阶段，无法判定两种模式的业务差别 |
| E-05 | 点击 Skills 单元格分数，弹层标题含候选人与维度；正文写“需求条件 → 评分标准 → 理由 → 证据 → 原文摘录”，实际仅显示“理由”段落 | 可打开下钻，但当前弹层未显示材料版本、位置、证据或原文摘录 |
| E-06 | 点击“添加候选人”，弹窗显示“该职位下所有已关联候选人都已在此对比中” | 页面没有列出其他岗位或未关联人；没有直接调用 API 验证拒绝码 |
| E-07 | 点击“刷新”后出现“已创建新快照，此前的快照均保留”；选择器从仅 v1 变为 v1、v2。v2 的“自上轮以来的变化”仍写“这是该对比集合的第一个快照”，并显示英文 baseline note | 页面层版本保留；历轮变化说明与 v2 事实矛盾。此次没有更新源评估，因此不能测试顾虑解决后的变化原因或自动过期 |
| E-08 | “导出对比”弹窗提供单页 PNG / 完整报告 PDF，写明会排除受限证据和联系方式；提交后提示“完整对比报告已导出（分页）” | 有确认和成功提示；未取得文件、任务最终状态或通知/审计记录，不能证明分页、可读性和内容裁剪 |
| E-09 | 对比页 DOM 与可见页面均无逐人下一步、批注或转交 F11 的操作区；页面底部即矩阵 | 当前角色不能从该对比页完成 PRD FR-14 / Journey 步骤 11；不能代替跨角色权限测试 |
| E-10 | 英文界面控件及摘要可切换；切回中文后，矩阵维度和差异摘要仍含 `Skills`、`Relevant Experience`、`Seniority`、`Compensation & Location Fit`，v2 note 为英文 | 中文界面未实现“所有文案都有翻译”的要求 |

**加载状态说明**：岗位详情刚打开时曾短暂显示关联数 0，随后更新为 2；本报告以加载完成后的状态为准，不将短暂空态当作数据丢失。当前对比仅两人、同阶段，不能把未出现三人/跨阶段/混合薪资的预期数据误判为功能失败。

## 6. 当前仓库静态核对（不等于线上实测）

- [`ComparePage.tsx`](../../../../hireos-screening/hireos-screening-front/src/pages/ComparePage.tsx) 的 `RoundChanges` 在变化数组为空时直接显示“第一个快照”，未按版本判断；页面 JSX 仅渲染 Header、模式、摘要/变化、矩阵及证据/加人/导出弹层，未见批注和下一步操作区。该实现与 E-07、E-09 相符，但不能证明线上构建与 HEAD 完全一致。
- [`comparisons.service.ts`](../../../../hireos-screening/hireos-screening-backend/src/comparisons/comparisons.service.ts) 在刷新时创建新 Snapshot 并把旧 current 改 stale；`export` 返回 queued 的 processing job。线上只看到了 toast，**未证实文件已生成或交付**。
- 当前 [`comparisons.controller.ts`](../../../../hireos-screening/hireos-screening-backend/src/comparisons/comparisons.controller.ts) 提供创建、读取、加人、刷新、导出接口，统一使用 WorkspaceGuard；未见批注/下一步接口及岗位角色专用校验。此为待隔离角色和线上 API 复现的实现风险，不写成已发生越权。
- 本次是线上人工功能与 UX 检查，没有改业务代码，也没有运行本地 build、lint、typecheck 或 test。没有声称自动测试通过。
