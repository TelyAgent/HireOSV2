## 1. 背景与目标

排序告诉 HR 先看谁，但到了要决定下一步时，需要把几个人放在一起看：各自强在哪、取舍是什么、还缺什么证据。对比的作用是呈现差异，不是替人选出赢家。

**目标**：同一岗位下多名候选人并排对比，突出与岗位相关的差异和证据缺口；每次刷新留下快照；每个人可以分别选择下一步。

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-1 | 从岗位工作台勾选候选人后点 **Compare candidates** 进入；保留来源列表的过滤条件；面包屑为 Jobs › 岗位 › Compare |
| FR-2 | 顶部显示岗位、对比名单、模式、时间 / 版本和刷新状态；提供 **Add candidate / Refresh / Export** |
| FR-3 | 矩阵以候选人为列、维度为行；默认适合 2～4 人并排，更多人时横向滚动、固定维度列 |
| FR-4 | 维度分组：核心差异、能力与资历、条件与可行性（薪资期望、地点、到岗时间）、工作方式（行为实例和待验证问题）、证据状态、下一步 |
| FR-5 | 矩阵上方是 AI Key Differences：主要差异、对岗位的意义、证据局限、最值得做的下一步验证；每条差异关联具体要求、涉及的候选人和证据 |
| FR-6 | 三个模式：Same stage、Current summary（默认）、Changes since last round；历轮变化显示新增证据、已解决 concern、未解决缺口和结论变化原因 |
| FR-7 | 视图选项：只看差异、显示未知、按岗位关键维度、保存个人视图 |
| FR-8 | 每个单元格可以下钻到具体材料版本和位置；证据和批注在右侧或抽屉中展开 |
| FR-9 | 批注带作者和时间，不覆盖 AI 原文，有修订历史 |
| FR-10 | 快照下拉可切换历史版本，旧快照显示版本、日期和「可刷新 / 已过期」标记 |
| FR-11 | **Refresh** 基于最新评估和标准生成新快照，版本号 +1，旧快照保留 |
| FR-12 | **Add candidate** 只能从同一岗位已关联的候选人中选择 |
| FR-13 | 导出一页差异图（PNG / PDF）和完整对比报告；人数过多时要求选择子集或分页输出 |
| FR-14 | 矩阵底部逐人选择下一步（笔试、面试、补资料、暂缓、不推进）；可以批量设同一动作后逐人修改；提交前列出精确名单、动作、路由、待满足条件和所需批准 |

## 4. 业务规则

| ID | 规则 |
|---|---|
| BR-1 | 只对比同一岗位下已确认的 Application；待确认推荐不进入对比 |
| BR-2 | 对比不表示选出录用者；不自动淘汰、推进或通知；生成对比或导出本身不发送任何通知 |
| BR-3 | 允许结论为「暂无明显全面领先者」；取舍用条件表达，不强制指定赢家，不编造录用概率 |
| BR-4 | 同一事实在摘要中不能被升级为更确定的判断 |
| BR-5 | 薪资统一币种、周期、税前 / 税后后才比较，否则显示不可直接比较及原因；缺失显示「未提供」，不为零 |
| BR-6 | 较低的薪资期望不增加能力分；公司规模、简历写法、姓名和照片不用于推断工作方式 |
| BR-7 | 未参加笔试 / 面试属于未评估，不是能力不足；完成轮次多不自动等于能力更高 |
| BR-8 | 不同测评题型、版本或评分标准不能直接混比数值；无有效映射时只并列证据并标注限制 |
| BR-9 | 对比成员固定保存，不随名单新增悄悄改变 |
| BR-10 | 源证据受限、撤回或更新时，快照标 stale / restricted；重新生成并复核后才能用于新的推进决定 |
| BR-11 | 快照只冻结输入和当时的结论，不冻结访问权；已撤权的证据不能再导出 |
| BR-12 | 导出按当前用户权限裁剪，默认不含联系方式和与岗位无关的个人资料；一页图必须包含岗位、时点、成员、关键差异、证据状态和重要限制，不缩成不可读的字体，不静默漏人 |
| BR-13 | 读取、刷新、改成员、批注、导出、提交下一步均写入审计 |

## 5. 数据

| 方向 | 对象 | 关键字段 |
|---|---|---|
| 输出 | ComparisonSet / ComparisonMember | set_id、岗位、成员 application 引用、创建者、协作者、用途、可见范围 |
| 输出 | ComparisonSnapshot | 版本、成员结果版本、目标岗位标准、维度 / 量尺映射、模式、阶段与证据状态、生成时间、输入清单、模型 / prompt 版本、访问限制、新鲜度 |
| 输出 | ComparisonCell | application、维度、值 / 单位、评估状态、来源阶段、证据引用、验证状态、可比性及原因 |
| 输出 | DifferenceSummary | 差异文本、涉及成员、要求、支持 / 反证、置信度、局限、待验证项 |
| 输出 | NextStepProposal | application、建议动作、依据快照、原因、缺口 |
| 输出 | ComparisonAnnotation | 作者、目标、正文、时间、引用快照、修订历史 |

## 6. 权限

- 只有对该岗位所有成员都有查看权限的人可以打开对比；部分无权限时对应单元格显示受限。
- 导出不包含受限的敏感依据。

## 7. 非功能要求

- 中英文界面下所有文案都有翻译（#26）。
- 评估或 concern 更新后，对比页及时标记过期（#27）。

## 8. 验收标准

| ID | 验收 | 对应 |
|---|---|---|
| AC-1 | 同岗位多人对比呈现核心差异和证据；没有明确赢家时不强制推荐第一名 | SCR-15、J8-3 |
| AC-2 | 一人已笔试、一人未笔试，后者显示未评估，不因资料少被判为低能力 | SCR-16 |
| AC-3 | 一次对比可以给全部选定人发笔试，也可以分别安排面试 / 补资料 / 暂缓；生成对比本身不通知 | SCR-17 |
| AC-4 | 跳过明确要求的笔试需要有效例外；optional / not_required 时不虚造测评结果 | SCR-18 |
| AC-5 | 每次刷新生成新快照，旧差异、原证据和变化原因可追溯 | SCR-19、J8-7～8 |
| AC-6 | 不同岗位、量尺或标准未映射时不混算；缺失的薪资、语言不写成零 | SCR-20、J8-5 |
| AC-7 | 一页导出可读且包含比较限制；成员过多时用子集或分页，不静默漏人 | SCR-21 |
| AC-8 | 权限撤销或来源更正后，不能用旧快照发起未经复核的新推进；批注不覆盖原评价 | SCR-22 |
| AC-9 | 只能添加同岗位已关联的候选人 | J8-6 |
| AC-10 | 三种模式都能切换并显示对应内容 | J8-2 |
