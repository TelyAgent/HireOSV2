## 5. UX/UI 发现与当前仓库静态核对

### 5.1 发现

| ID | 级别 / 类别 | 角色及步骤 | 证据、影响与最小修复 | 复测标准 |
|---|---|---|---|---|
| UX-F07-01 | P2 / state、clarity | Recruiter，旅程步骤 3 | E-04 成功提示“进入初筛队列”，E-05/E-06 人工状态为“待人工复核/待复核”，而 PRD AC-4 写“等待推进”。虽然可看出尚未由人推进，跨页面用词可能使用户不清楚关联、初筛复核和下一步决定的关系。统一产品状态命名，并在初筛页说明下一位处理人和动作。 | 关联完成后，推荐页、初筛页、岗位列表和任务页使用同一业务状态；用户能区分 AI 筛选完成与人工决定未完成。 |
| UX-F07-02 | P2 / clarity | Recruiter，旅程步骤 1 | E-02 只见“Strong match signal”，没有数字置信度；UC-F07-01 写“理由、置信度”。文字等级可以辅助判断，但若需要具体置信度或评分来源，当前页面不充分。先确认文档的“置信度”是否必须是数值，再展示定义或调整用例。 | 对照已确认的产品口径，页面能解释匹配信号及其含义。 |
| UX-F07-03 | P2 / next_action | Recruiter，旅程步骤 3 | E-04 成功 toast 说“已进入初筛队列”，但原推荐卡在刷新前仍暂时显示“待确认”和原按钮；刷新后才显示“已确认”。异步刷新期间容易让用户误以为可再确认。提交成功后立即同步状态或显示明确的加载状态。 | 成功响应后无需手动刷新，卡片切为“已确认”，操作入口只剩下一步。 |
| UX-F07-04 | P1 / role_information_fit、efficiency | Recruiter，旅程步骤 1～2 | E-02 的推荐页显示 AI 理由与未知项，但没有明确的“查看候选人档案/简历”入口；只有依浏览历史跳转的“返回”箭头。用户补充指出审核人无法据此充分判断是否关联。当前仓库 `JobRecommendationsPage.tsx` 与 `useGoBack()` 也显示：从岗位工作台进入时，返回不保证到候选人档案。为当前候选人提供明确、稳定的资料入口，并允许返回同一条推荐继续处理。 | 从候选人页、岗位工作台及直达链接进入推荐页时，均能一键查看对应候选人资料，返回后仍定位原推荐；缺少原始简历时明确说明资料范围。 |

### 5.3 静态观察（不能视为线上构建或线上实测）

- 当前仓库 [`linking.service.ts`](../../../../hireos-screening/hireos-screening-backend/src/linking/linking.service.ts) 检查岗位开放、候选人有效、标准和档案版本；在事务内创建或复用 Application、记录 LinkDecision、切换任务，并在事务后发起自动筛选。线上未核对 DB、审计和任务持久化。
- 当前仓库 [`linking.controller.ts`](../../../../hireos-screening/hireos-screening-backend/src/linking/linking.controller.ts) 的确认接口只挂 `WorkspaceGuard`；[`linking.service.ts`](../../../../hireos-screening/hireos-screening-backend/src/linking/linking.service.ts) 所示确认路径未见岗位负责人/角色授权判断。与 F07 角色规则存在**待线上隔离账号复现的高风险实现缺口**，不据此声称线上已发生越权。
- 当前仓库 [`JobRecommendationsPage.tsx`](../../../../hireos-screening/hireos-screening-front/src/pages/JobRecommendationsPage.tsx) 对 proposed 展示“选择其他职位/暂缓/拒绝/确认”，confirmed 展示“打开初筛”；未见页面层按岗位负责人隐藏操作的条件。该观察与角色用例的文档 known gap 一致。
- 未找到 F07 专项自动测试；本次没有运行本地 build/lint/typecheck/test。本报告的测试结果仅为上述线上浏览器操作，不将静态阅读当作自动测试通过。

## 6. 风险、后续复测与审查结论

1. **优先关闭权限证据**：在隔离角色账号中对岗位负责人 Recruiter/HM、非负责人 HM、HR Approver、Viewer 分别验证 UI 与确认/拒绝/暂缓 API；检查非负责人 403 和审计可见范围。无此证据，不能按 UX 标准宣布通过。
2. 用文档定义的 `S_dataset`、`S_linked`、`S_job_closed` 和虚构候选人补齐拒绝、暂缓、多岗位、重复/并发、关闭/过期路径。每条至少核对页面、API/DB 和 LinkDecision/任务审计；通知用隔离 mock 或外发日志核对零消息。
3. 在可控测试环境注入自动筛选失败，验证关联保留且可重试。请勿把本次线上成功筛选推断为失败路径通过。
4. 修复或明确豁免 UX-F07-01～04，优先补上关联决策所需的候选人资料入口，并做键盘、焦点和 200% 缩放复测；记录线上构建号、测试角色、时间和截图/录屏。
