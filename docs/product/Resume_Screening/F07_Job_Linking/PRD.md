## 1. 背景与目标

AI 推荐的岗位不一定对。把候选人正式纳入某个岗位的考虑，必须是人的决定；而纳入考虑和决定下一步（笔试、面试等）又是两件事。

**目标**：只有人工确认才建立正式 Application；确认关联不推进、不邀请、不通知候选人；关联和下一步在系统中是两个独立动作。

匹配信号沿用文字等级（匹配证据强、有一定匹配证据、匹配证据有限），不显示数值或百分比。每张当前推荐卡提供可键盘展开的解释，说明等级表示当前档案与岗位标准之间的匹配证据强弱，不表示已关联、已推进或录用。理由与未知项保留在同一卡片；证据不足、人工添加及不符合资格分别显示非等级状态和对应说明。过期推荐不显示当前匹配等级。

## 2. 范围

| 包含 | 不包含 |

## 3. 功能需求

| ID | 需求 |
|---|---|
| FR-1 | 在「适合的岗位」页和关联确认任务中，查看候选人、岗位、AI 理由、关键未知项、是否已有正式关系 |
| FR-2 | 每条推荐可选 **Confirm job link**、**Dismiss recommendation**、暂缓；也可以人工选择其他岗位 |
| FR-3 | 确认弹窗写明：确认「应把 X 考虑用于 Y 岗位」，**不会推进、不会邀请、不会发送通知**；列出候选人、岗位及标准版本、是否已有申请（有则复用）、确认人与时间；原因可选填 |
| FR-4 | 确认后提示已关联，生成「复核初筛并选择下一步」任务；候选人出现在岗位的 Linked candidates 中，人工状态为「等待推进」 |
| FR-5 | 拒绝推荐后，该推荐从待确认列表移除，不产生申请，候选人仍在简历库 |
| FR-6 | 暂缓的推荐保留在任务中，任务不算完成 |
| FR-7 | 推荐过期（岗位或资料已更新）时提示刷新后再处理 |
| FR-8 | 候选人主动投递或从指定岗位上传时，保留原申请意向，作为待确认关联显示 |

## 4. 业务规则

| ID | 规则 |
|---|---|
| BR-1 | 推荐状态：proposed → confirmed / dismissed / deferred；来源变化时可变为 stale / withdrawn |
| BR-2 | 只有 LinkDecision = confirm 才创建或复用 Application；dismiss / defer 不创建 |
| BR-3 | 同一招聘周期内重复确认只返回已有 Application；重新申请需要显式开启新周期 |
| BR-4 | 并发确认使用版本前置条件和唯一约束，只保留一个有效关联 |
| BR-5 | 确认前重新校验：岗位仍开放、资料仍有效、确认人有权限；过期提案需要刷新复核 |
| BR-6 | 拒绝推荐不等于拒绝候选人，也不删除简历库资料 |
| BR-7 | 主动投递不能绕过人工确认；上游传入的「已关联」必须有可追溯的人工确认，只有 AI 结果的不接受 |
| BR-8 | 已经由人确认过的 Application 只复用，不重复要求确认 |
| BR-9 | 同一页面可以连续完成关联和下一步，但后台记录为两个独立动作，分别审计 |
| BR-10 | 关联前评估在输入、模型和策略完全一致时可以被筛选复用，不改写原记录 |

## 5. 数据

| 方向 | 对象 | 关键字段 |
|---|---|---|
| 输入 | CandidateJobRecommendation | 推荐状态、评估引用、版本 |
| 输出 | LinkDecision | 处理结果、候选人 / 岗位 / 推荐引用、确认人、时间、理由、expected_version、确认后的 application 引用 |
| 输出 | Application | candidate、job、招聘周期、来源、关联人、关联时间、关联原因 |
| 输出 | HumanTask | 关闭 link_confirmation，新建 screening_review |

## 6. 权限

- 由岗位配置的负责人确认；Recruiter / TA 和 Hiring Manager 担任岗位负责人时都可以，不默认只给 Recruiter。HR Approver、Viewer 不能确认关联。
- 无权限的用户看不到确认按钮，或按钮不可点并说明原因。

## 7. 非功能要求

- 双击确认只产生一次关联。
- 关联成功后的自动筛选失败，不回滚关联。

## 8. 验收标准

| ID | 验收 | 对应 |
|---|---|---|
| AC-1 | 确认前 Application 数量不变；可以确认一个或多个岗位，逐项审计 | SCR-26、J5-4～5 |
| AC-2 | 拒绝推荐不删除候选人；暂缓保留任务；关联成功不发任何通知 | SCR-27、J5-5、J5-7 |
| AC-3 | 同岗位重复确认、并发确认只保留一个有效关联；岗位关闭或输入过期需要重新处理 | SCR-28、J5-8 |
| AC-4 | 关联后人工状态为「等待推进」，不是「已推进」 | J5-6 |
| AC-5 | 已关联关系不重复要求确认 | SCR-29 |
| AC-6 | 同一人关联不同岗位形成独立 Application，评分和权限不混用 | SCR-04 |
