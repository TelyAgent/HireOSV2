### Problem

同一线上页面同时显示 HR 与 HM 的确认控件；仓库实现按请求中的 `role` 写入确认槽位。本次未做越权 API 实测，线上越权是否可复现仍待验证。

### User Outcome

只有获授权的 HR 或 HM 能确认各自负责的评估包，操作可追溯。

### Scope

I11 确认按钮可见性、服务端角色校验和确认审计。

### Non-goals

不改变必须双方分别确认的业务规则。

### Acceptance Criteria

- AC-1: 服务端根据已验证身份判定确认权限，不以客户端提交的角色字段作为授权依据。
- AC-2: HR、HM 只能完成各自授权的确认；未授权身份调用确认 API 被拒绝。
- AC-3: 自动测试覆盖 HR、HM、Interviewer 的允许与拒绝路径。
